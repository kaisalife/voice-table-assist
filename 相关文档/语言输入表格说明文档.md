# 语言输入表格说明文档（VoiceTableAssist）

> **文档定位**：面向开发人员的上手文档，覆盖"语音 → 表格单元格 JSON"全链路的结构、配置、接口、扩展与陷阱。
> **最小可用集**：`Program.cs` + `appsettings.json` + `models/`（raner/embedding/asr）+ sherpa-onnx 原生 server，单进程、单端口 **15232** 即可跑通。
> **最高频操作**：换表/改内容优先重新 `POST /import_table`（自动重建向量库与语音资源），一般不用动代码；调参数优先改 `appsettings.json`。
> **勘误与缺陷声明（必读）**：`语音` **Cordova 原生录音插件在本项目中完全未考虑、未落地**。
>
> **源码地址**：<https://github.com/kaisalife/voice-table-assist>；**models 不在 Git 中**，首次进入 `app/VoiceTableAssist/` 执行：
> ```
> pip install modelscope
> modelscope download --model yanxiashuiyun/VoiceTableAssist --local_dir .
> ```
> 完成后出现 `models/{raner, embedding, asr}` 即可构建/运行。

## 一、项目简介与技术栈

把"浏览器说话 → 表格填数"做成一个**单进程、单端口(15232)** 的自包含服务：本地离线流式 ASR（sherpa-onnx）+ 进程内 RaNER 三元组抽取 + gte-base-zh 向量检索定位单元格。**零云端依赖、零密钥、不依赖外部 Node NER、不做跨服务 HTTP 桥**。

- **支持多表**：一个实例承载多张检验表，按表名持久化各自的向量库与语音特化（同音纠正/热词）资源，导入/查询/语音按表名切换，空闲或显式卸载。
- **语音单连接**：同一时刻只允许一路语音连接，其余握手直接回 **HTTP 409**，从根上规避切表/抢占问题。
- **技术栈**：.NET 8（`Microsoft.NET.Sdk.Web`，self-contained 发布免装运行时）、ONNX Runtime 1.20.1（RaNER + gte-base-zh 进程内推理）、sherpa-onnx 流式 Zipformer 中文 ASR（独立子进程，端口 6006）、原生 WebSocket（Kestrel）。
- **服务托管**：Windows=`UseWindowsService`，Linux=`UseSystemd`，按运行平台自动分支，代码不改。

**关键链路（语音）**：
`麦克风(voice-mic.js, 16kHz float32 PCM) → WS /api/speech/asr/stream?table= → SherpaAsrBridge → sherpa-onnx(6006) 流式识别 → 同音/领域纠正 → 端点检测(说完停顿约 2s 切句) → 300ms 收尾 → RaNER 拆三元组 → 主客体拼接查向量库得 (row,column) → 回传 type=cells 事件`

**关键链路（文本）**：
`POST /text_to_json {text} → RaNER 三元组 → 向量库查坐标 → [{row,column,values}]`

## 三、本地运行

```powershell
# 构建
cd VoiceTableAssist
dotnet build -c Release

# 直接运行（前台，验证页 http://127.0.0.1:15232/）
.\VoiceTableAssist.exe

# 推荐：部署自检（临时拉起+就绪探测+可选自测，关掉脚本即停）
.\deploy-check.ps1
.\deploy-check.ps1 -Selftest
```

- 监听地址默认 `http://0.0.0.0:15232`（`Urls` 配置）。
- 启动即激活 `default` 表并自检 RaNER/embedding 装载；sherpa 子进程**懒启动**（首次语音连接时拉起）。
- 打包发布：`powershell -ExecutionPolicy Bypass -File .\publish.ps1`（产出 `app\publish\voice-table-assist-win-x64.zip`，含模型/sherpa/selftest/cordova/文档，目标机解压即用，**无需 .NET 运行时**）。
- 注册为 Windows 服务（可选）：

```powershell
nssm install VoiceTableAssist "D:\app\voice-table-assist\VoiceTableAssist.exe"
nssm set    VoiceTableAssist AppDirectory "D:\app\voice-table-assist"
nssm start  VoiceTableAssist
```

> 前置条件：`models/` 随仓库提供；`sherpa-onnx/`（原生 server + 热词资源）由发布脚本拷贝。**Linux 版需自备** **`sherpa-linux/`**：官方 release 的 `sherpa-onnx-vX-linux-x64.tar.bz2` 解包后整目录放到脚本所在目录下（含 `bin/sherpa-onnx-online-websocket-server` 与 `models/`、`hr/`）；执行 `powershell -ExecutionPolicy Bypass -File .\publish-linux.ps1`，产出 `app\publish\voice-table-assist-linux-x64.zip`（与 Windows 版同目录，不改动 Windows 版产物）。

# 语音表格辅助技术方案——模型选型与训练

> 依据当前实现整理，供技术评审与后续迭代参考。

## 一、语音 → 文字模型（ASR）

### 1. 主流模型及优缺点

| 模型/方案                    | 优点                       | 缺点                             | 适用场景        |
| ------------------------ | ------------------------ | ------------------------------ | ----------- |
| OpenAI Whisper           | 多语言能力强、开源、社区生态成熟         | 模型较大、实时性一般、需较高算力               | 离线转写、多语言混合  |
| Wav2Vec 2.0 / XLS-R      | Meta 开源、支持微调、学术引用广       | 中文效果需额外微调、工程链略重                | 英文/多语言、研究场景 |
| Conformer + Kaldi/sherpa | 工业级流式识别、实时性好、可本地化        | 中文模型需专门训练、生态碎片化                | 实时语音交互、端侧部署 |
| 商业云 ASR（阿里云/讯飞/腾讯云）      | 准确率高、接入简单                | 需联网、按量计费、数据外泄风险                | 快速上线、预算充足   |
| sherpa-onnx              | 本地离线、C++ 运行时、支持流式、模型选择灵活 | 模型质量依赖所选 checkpoint、热词/纠错需自行维护 | 私有化部署、工业现场  |

### 2. 选择的模型与效果

**选择模型**：`sherpa-onnx`（本地流式 ASR）。

**选型理由**：

1. **离线运行**：目标场景为工厂/现场，网络不稳定，必须本地部署。
2. **流式识别**：支持 WebSocket 实时推流，边说边识别。
3. **资源可控**：可选不同尺寸模型，在准确率与延迟间取舍。
4. **集成方便**：C# 进程内启动 sherpa-onnx server，通过本地 WebSocket 转发音频。

**目前效果**：

| 项   | 现状                                          |
| --- | ------------------------------------------- |
| 采样率 | 16kHz，float32 PCM                           |
| 冷启动 | 首次语音连接约 8\~10s（含模型加载），期间前端收到 `loading` 帧    |
| 实时性 | 流式返回 `partial` / `final` 结果                 |
| 准确率 | 标准普通话、环境噪声可控时，常规数字/术语识别可用；存在同音字误差，需后端同音纠正兜底 |

## 二、文字 → JSON 模型

### 1. 主流模型及优缺点

| 模型/方案              | 优点                     | 缺点            | 适用场景        |
| ------------------ | ---------------------- | ------------- | ----------- |
| BERT-CRF           | 准确率高、可解释性好、适合槽位固定      | 需标注数据、泛化能力中等  | 结构化抽取、表单填槽  |
| BiLSTM-CRF         | 轻量、训练快                 | 上下文理解弱于 BERT  | 简单序列标注      |
| GPT / 大模型          | 零样本/少样本能力强、说法灵活        | 模型大、延迟高、输出不稳定 | 开放域对话、复杂语义  |
| 通用信息抽取（UIE 等）      | 针对中文优化                 | 需适配领域         | 中文 NER、关系抽取 |
| RaNER (ModelScope) | 中文实体识别专用、模型适中、可导出 ONNX | 需微调、领域适配      | 中文 NER、工业语义 |

### 2. 选择的模型

| 环节   | 模型                                                                     | 作用                    |
| ---- | ---------------------------------------------------------------------- | --------------------- |
| 实体拆分 | `RaNER`（`damo/nlp_raner_named-entity-recognition_chinese-base-news`）微调 | 拆出「主体 / 客体 / 值」       |
| 表格定位 | `gte-base-zh` 向量检索                                                     | 「主体 + 客体」拼成短语，查向量库得坐标 |

**选型理由**：

1. **RaNER 适合中文实体边界**：对「主体 / 客体 / 值」的 BIO 标注友好。
2. **gte-base-zh 语义向量**：支持「词面不同、语义相同」的模糊匹配，解决同一单元格的多种说法。
3. **均可本地运行**：满足离线部署需求。

### 3. 训练方法

1. **数据生成**：`generate_data.py` 基于 `moban.txt` 模板，生成 6×6 表格的多种说法，覆盖行先说/列先说、带/不带连接词、单主体多客体、多主体多客体、长序列等。
2. **标签体系**：7 类 BIO（`O`, `B-SUB`, `I-SUB`, `B-OBJ`, `I-OBJ`, `B-VAL`, `I-VAL`）。
3. **微调**：`train.py`，BERT + CRF 架构，AdamW + OneCycleLR，参数如下：

| 参数           | 值          |
| ------------ | ---------- |
| `MAX_LEN`    | 128        |
| `BATCH_SIZE` | 128        |
| `EPOCHS`     | 10         |
| `LR`         | 2e-5       |
| `OPTIMIZER`  | AdamW      |
| `SCHEDULER`  | OneCycleLR |

4. **导出**：`export.py` 输出 ONNX + CRF 转移矩阵 + 配置文件，供 C# 端 Viterbi 解码。
5. **部署**：复制到 `text_to_json/models/raner/`，重启服务。

### 4. 目前效果

| 项      | 现状                        |
| ------ | ------------------------- |
| 训练覆盖句式 | 拆分稳定                      |
| 未生成说法  | 依赖 gte 向量语义泛化             |
| 边界     | 句子越拗口、冗余越多、词序越乱，越可能掉回相邻坐标 |

***

1. **语音流识别编排（单连接门卫）**：握手路径同步解析 `?table=`（未注册→404），`EngineHost.TryAcquireSession()` 保证**同时仅一路会话**（二路→409）；会话内同步激活对应表，HR 规则随连接捕获不随切表漂移；连接断开/异常由 `finally` 释放会话。
2. **端点检测 + 静默自动提交**：sherpa 端点检测在说完停顿约 **2 秒**（`SherpaServer:Rule1TrailingSilence`）时切句输出 `final`，服务端 300ms（`Interaction:SilenceMs`）后自动解析并**直发** **`type=cells`** 的解析结果；客户端也可发 `{"type":"stop"}` 立即提交。语音累计上限 **500 字**（`Interaction:MaxChars`），**提交后累计保留**（后续语句可省略行名、沿用前文主体），超限才清空并停会话。前端只负责开关麦克风和收结果。
3. **RaNER 三元组抽取**：BERT+CRF 序列标注，标签集 `O / B-SUB / I-SUB / B-OBJ / I-OBJ / B-VAL / I-VAL`；把"序号一，二号列，十七点八四"拆成 主体=序号一 / 客体=二号列 / 数值=十七点八四，**支持无标点连说与一句话多组**。
4. **向量检索定位单元格**：主客体拼短语（CellPhraseGenerator：行描述 3 种 × 列描述 4 种 × 正反序，**测量值不反序**，每格 21 条——已剔除阿拉伯数字变体，模型词表无数字）→ gte-base-zh 向量化 → 查该表 VTX1 二进制向量库 → 得 (row, column)；数值经 `ChineseNumeral` 归一（"十七点八四"→17.84，"负九十五"→-95）。
5. **同音纠正（HR）+ 热词**：每表按导入内容自动生成 `hotwords.txt`（字级 token 空格分隔，热词分数 2.0）与 `hr_rules.txt`（同音替换规则，需拼音表），并**聚合所有表的热词**写入 `tables/current/hotwords.txt`（sherpa 仅启动时读该文件），随后自动后台重启 sherpa 加载（约 7s，2s 防抖合并）；识别文本先纠正再抽取。资源变化可用 `POST /api/table/voice` 在线重建。
6. **多表管理**：`/import_table` 构建 `models/embedding/tables/<key>/cell_index.bin` + 更新 registry + 激活 + 重建该表语音资源；向量索引"写时拷贝"（临时文件+`File.Move`），导入期间查询仍用旧索引，**绝不读到半成品**；同表重复导入 last-write-wins；`/api/table/unload` 只清内存不删盘；空闲 **30 分钟**自动卸载（`Tables:IdleTimeout`）。

## 六、配置字段说明（改这里就行）

文件：`appsettings.json`。优先级：**系统环境变量 > app/.env > appsettings.json**；环境变量用双下划线，如 `AsrProvider__Endpoint`。修改配置需**重启服务**生效（语音资源例外，见第五节第 5 条）。

| 段.键                                          | 默认值                                                          | 说明                                                  |
| -------------------------------------------- | ------------------------------------------------------------ | --------------------------------------------------- |
| `Urls`                                       | `http://0.0.0.0:15232`                                       | 对外监听地址                                              |
| `AsrProvider:Endpoint`                       | `ws://127.0.0.1:6006`                                        | sherpa 流式识别服务地址（本机子进程）                              |
| `AsrProvider:SampleRate`                     | `16000`                                                      | 上行采样率（Hz），**固定 16k**                                |
| `Interaction:SilenceMs`                      | `300`                                                        | final 到达后的提交收尾延时（毫秒），端点检测已先行切句               |
| `Interaction:MaxChars`                       | `500`                                                        | 语音累计上限（字），**提交后保留累计**；超限清空并停会话                  |
| `Models:LazyLoad`                            | `true`                                                       | 语义引擎懒加载（health 的 `modelsLoaded` 为 false 属正常）；**sherpa 语音模型常驻不卸载** |
| `Models:IdleUnloadSeconds`                   | `180`                                                        | 语义引擎空闲卸载（秒）；sherpa 不受影响                            |
| `SherpaServer:EnableEndpoint`                | `true`                                                       | 端点检测（说完停顿自动切句输出 final）——关闭则只能靠 stop 提交         |
| `SherpaServer:Rule1TrailingSilence`          | `2.0`                                                        | 停顿多少秒切一句（Rule2/3 置 3600 禁用）                       |
| `SherpaServer:ExePath`                       | `sherpa-onnx/sherpa-onnx-online-websocket-server.exe`        | 相对发布目录                                              |
| `SherpaServer:Encoder/Decoder/Joiner/Tokens` | `models/asr/sherpa-onnx-streaming-zipformer-zh-2025-06-30/…` | ASR 模型文件                                            |
| `SherpaServer:DecodingMethod`                | `modified_beam_search`                                       | 解码方法                                                |
| `SherpaServer:HotwordsFile`                  | `sherpa-onnx/hr/tables/current/hotwords.txt`                 | 热词文件（default 表路径，其余表在 `tables/<key>/`）              |
| `SherpaServer:HotwordsScore`                 | `2.0`                                                        | 热词加权分数                                              |
| `SherpaServer:Port`                          | `6006`                                                       | sherpa 子进程端口                                        |
| `SherpaServer:NumThreads`                    | `4`                                                          | 推理线程数                                               |
| `SherpaServer:StartupTimeoutSeconds`         | `30`                                                         | 子进程启动超时                                             |
| `Tables:BaseDir`                             | `embedding/tables`                                           | 多表向量库根目录（→ `models/embedding/tables`）               |
| `Tables:HrBaseDir`                           | `sherpa-onnx/hr/tables`                                      | 多表语音资源根目录                                           |
| `Tables:DefaultTable`                        | `default`                                                    | 缺省表名；旧 `models/embedding/cell_index.json` 启动时自动登记为它 |
| `Tables:IdleTimeout`                         | `00:30:00`                                                   | 表空闲卸载超时                                             |
| `Tables:IdleCheckInterval`                   | `00:01:00`                                                   | 空闲巡检间隔                                              |

| `Homophone:TableRules` / `TableDir`          | `sherpa-onnx/hr/tables/current/…`                            | 当前表同音规则（default 表路径）                                |

### 接口总表（单端口 15232）

| 方法   | 路径                              | 说明                                                                                 |

| GET  | `/api/health`、`/healthz`        | 健康检查（别名兼容），返回 `configured/provider/activeTable/modelsLoaded`                       |


**deploy-check.ps1**（用法：`.\deploy-check.ps1 [-Selftest]`）：临时拉起服务+就绪探测，验证 `/api/health` 与模型装载，关脚本即停。

**selftest/selftest.ps1**（用法：`.\selftest.ps1 [-Base http://127.0.0.1:15232] [-Only http|ws|asr] [-AsrTable default] [-AsrText "硬度一号是五十点零"] [-Wav "录音.wav"] [-ReadyTimeoutSec 60]`）：一体化自测，三节按序全跑，退出码 0=全通过（SKIP 不算失败）——

**selftest/convert-to-wav.ps1**（用法：`.\convert-to-wav.ps1 -Source "录音.m4a" [-Output "录音.wav"]`）：用 Windows 内置 MediaTranscoder 把任意音频（m4a/mp3/...）转成 16k/16bit/mono PCM wav；不依赖 ffmpeg，适合无法从 GitHub 下载 ffmpeg 的环境。

## 十、规范与要求

- 上行音频：**16kHz、float32、单声道 PCM**（浏览器由 AudioWorklet 采集透传；对接 16bit 采集源需前端转 float32）。
- **同一时刻仅一路语音连接**，多端抢用需在前端排队/互斥。
- 表目录一律按 registry 的安全 `key` 查找，**不直接拼表名进路径**（防路径穿越）。
- 含中文的 `.ps1` 必须 **UTF-8 with BOM**（PowerShell 5.1 否则按 GBK 解析报错）。
- 探活用 **`127.0.0.1`** 不用 `localhost`（IPv6 解析坑）。
- 语音累积上限 **120 字**、静默 **2500ms** 自动提交。
- 模型目录解析：默认相对可执行文件目录；`RANER_MODEL_DIR` 可覆盖（其下 `tables/` 随之定位）。
- **语音输入规范**：
  - **行名开头**：每次输入开头必须说明行名（如"硬度"、"序号"），告知系统要填入哪一行。
  - **列式填入**：也支持逐列填入，此时需先说明列号（如"第一列"），再说明行标签（如"硬度是十，圆度是二十"）。
  - **助词灵活**：行名后可接 `测量值是` / `填` / `改为` / `为`，或不加助词直接接值。例如：测量值一是五十点零 / 测量值二填四十九点九九 / 测量值三改为五十一点五 / 测量值四为六十点七五 / 测量值五八十（不加助词直接接值）。
  - **跳位填入**：无需一次说完一整行，可跳着输入（如"一号是五十，三号是二十"），但每次至少填入行中一个位置。
  - **单值修改**：直接说"行名 + 位置 + 值"，如 `硬度，测量值二（或二号）是十`，即可将硬度行第二列的值修改为 10。只要把**行号 + 列号 + 值**说清楚即可。
  - **标准样例**：`巡检登记，硬度，测量值一是五十点零，测量值二是四十九点九九，测量值三是五十一点五，测量值四是六十点七五，测量值五是六十六点七五，测量值六，四十八点七七`（可省略"是"直接说值；"测量值几"可换成"几号"以减少字数；"巡检登记"可省略，直接从行名开始）。

## 十一、常见问题

| 现象                                   | 处理                                                                         |
| ------------------------------------ | -------------------------------------------------------------------------- |
| health 用 `localhost` 打不开             | 改用 `http://127.0.0.1:15232/api/health`                                     |

## 十二、缺陷与未覆盖项

### 缺陷点：Cordova 原生录音插件未实现（已提供 WebView 采集替代路径）

- **来源**：`语音集成方案-概要.md` 第二章（2.1–2.3）规划了 Cordova 原生录音插件 `wesunsoft-pcm-recorder`：原生 `AudioRecord`（VOICE\_RECOGNITION / 16kHz / 16bit / 单声道）、200ms 一块 Base64 经 `PluginResult` 流式回传 JS、运行时申请 `RECORD_AUDIO`。
- **现状**：**原生插件仍未实现**（仓库无插件源码、无 `compiler-3.3` 工程）；但已落地**不需要原生插件的替代路径**——`cordova/` 安卓壳模板（config.xml 声明 `RECORD_AUDIO` 权限与 `scheme=http`、build.ps1 从 wwwroot 同步页面三件套）。壳内页面 origin 为 `http://localhost`（WebView 视为安全上下文），`getUserMedia` 由 cordova-android 10+ 的 `SystemWebChromeClient` 自动走运行时权限弹窗，无需自写权限回调。
- **当前实现**：音频输入为壳内/浏览器侧 `getUserMedia + AudioWorklet`（`wwwroot/voice-mic.js` + `audio-capture-worklet.js`），Cordova 壳只负责提供安全上下文与权限，采集仍走 WebView。
- **影响**：需要原生 `AudioRecord`（16bit、VOICE_RECOGNITION 音源）的概要方案仍不可用；常规平板语音录入用壳模板即可。
- **若必须原生插件**：按概要 2.2 另行开发。本项目侧协议只需保证"16kHz PCM 二进制经 WS 上行"不变；注意插件原生输出为 **16bit PCM**，本项目上行格式为 **float32**，需在前端做一次 `int16 → float32` 转换后即可对接，其余链路零改动。

### 勘误：方案文档与实际实现的差异

| 概要文档描述                                         | 本项目实际                                                                    |
| ---------------------------------------------- | ------------------------------------------------------------------------ |
| 火山引擎云端流式 ASR（`VolcengineAsr:ApiKey` 密钥、外网 443） | **sherpa-onnx 本地离线 ASR**，无密钥、无外网依赖                                       |
| 后端另起 .NET 8 Windows 服务网关 + 平板 WebSocket 直连     | 单进程单端口 15232 自包含服务                                                       |
| Cordova 插件采集（见上）                               | 已落地 `cordova/` 壳模板：WebView getUserMedia 采集（无需原生插件），HTTP/WS 连网关        |
| 前端 `speech-command.js` 解析"序号+列号+值"后派发事件写 Vue 表 | 后端 RaNER+向量库直接解析出 `{row,column,values}`，旧 `speech-command.js` 已删除     |

两文档冲突时，以本仓库实现与本说明文档为准。

## 十三、开发者上手清单（Checklist）

1. 环境：安装 .NET 8 SDK（`global.json` 锁版本）；确认仓库含 `models/`，缺 `sherpa-onnx/` 时先跑 `publish.ps1` 补齐（Linux 需自备 `sherpa-linux/`）。
