# 安卓化方案（方案 A：纯 C/C++ + Android Native Service + AIDL）

> **目的**：把 `smart-inspection-voice-gateway-dotnet8`（现 .NET 8 + sherpa-onnx + 本地 ASR / NER / 嵌入 / HR / GTCRN 降噪）整套能力**塞进安卓平板，离线运行，由企业 App 通过 AIDL 调用，**不**带 UI**。
>
> **状态**：设计稿，多处标 `【待定】`——这些是必须跟企业 App 团队 / 集成方对齐后才能定的事项。

---

## 0. 范围与边界

### 0.1 要做的事

- 把现 .NET 8 网关的 **ASR + GTCRN 降噪 + RaNER + 嵌入 + 同音纠正 + 多表管理 + partial/final/cells 编排** 全部跑在平板本地。
- 暴露一套 **Android AIDL 接口**，让外部企业 App 通过 Binder 调。
- 工程实现：纯 **C/C++**，Android 端一个 **Native Service** 进程；不写 Java/Kotlin 业务代码（AIDL 自动生成的桩除外）。

### 0.2 不做的事

- **不**做 UI（前端由企业 App 负责）。
- **不**保留现网 .NET HTTP/WS 端点（除非企业 App 要求，否则平板只通过 AIDL 暴露）。
- **不**带 `sherpa-onnx-online-websocket-server.exe` 这个进程（不跨 ABI）；改用 **JNI 调 sherpa-onnx C++ 库** 起 `OnlineStream` / `OnlineRecognizer`。

### 0.3 跟现网代码的关系

- **不复用 C# 代码**：.NET 那层与 Native Service 是两个独立进程，跨进程只能 AIDL。
- **可复用模型 ONNX**：`encoder.onnx` (588MB) / `decoder.onnx` / `joiner.onnx` / `model.onnx` (RaNER) / `model_quantized.onnx` (gte-base-zh) / `gtcrn_simple.onnx` 全部直接拷贝；`tokens.txt` / 热词 / HR 规则表 / 表注册表等数据文件直接拷（路径改 Android 内部存储）。
- **算法逻辑逐句翻译**：C# 的 `SherpaAsrBridge` / `GtcrnDenoiser` / `RaNerEngine` / `EmbeddingEngine` / `TableVectorManager` / `HomophoneReplacer` / `VoiceInteractionSession` 全部重写成 C++，放同一进程（一个 Native Service）——减少 IPC。

## 3. AIDL 对外接口（草稿）

> 命名空间 `com.vta`；包名沿用 `smart-inspection-voice-gateway` 派生（占位）。所有 Java/Kotlin 代码**只由 AIDL 编译器自动生成**，不手写。

### 3.1 AIDL 主接口

```java
// aidl/com/vta/IVtaService.aidl  ——  AIDL 语法，业务侧不实现
package com.vta;

import com.vta.PcmFrame;
import com.vta.SessionState;
import com.vta.TableInfo;
import com.vta.CellHit;

interface IVtaService {

    // 生命周期
    int getVersion();
    String health();                       // 返回 "ok" / 启动中 / 错误

    // 表格管理  【待定：增删查?】
    List<TableInfo> listTables();
    TableInfo getTable(String name);
    // int importTable(String jsonOrCsv);   // 【待定】
    // int removeTable(String name);        // 【待定】

    // 热词 / 同音纠正  【待定】
    // int setHotwords(String tableName, String[] words, float score);
    // int setHrRules(String tableName, String path);

    // 语音会话：流式接口
    int openSession(String tableName, int silenceMs);    // 返回 sessionId；409 = 已有
    int pushPcm(int sessionId, in PcmFrame frame);      // 喂 float32 PCM（每块 10~100ms）
    SessionState getState(int sessionId);
    CellHit[] pollCells(int sessionId, int maxN);       // 阻塞拉取累积的 cells
    int closeSession(int sessionId);
}
```

回调用 **轮询 `pollCells`**，避免 AIDL 跨进程回调的复杂时序——更稳、调试容易。

### 3.2 Parcelable

```java
// PcmFrame.aidl —— 16kHz float32 单声道 PCM 块
package com.vta;
parcelable PcmFrame {
    long timestampMs;       // 企业 App 自己写，服务端不解析
    float[] samples;        // 10~100ms 长度（160~1600 样本）
}

// SessionState.aidl
package com.vta;
parcelable SessionState {
    int sessionId;
    String tableName;
    String phase;           // "idle" / "listening" / "endpointing" / "closed"
    String partial;         // 当前 partial 文本
    long lastPartialMs;
}

// TableInfo.aidl
package com.vta;
parcelable TableInfo {
    String name;            // 表名（如"锅炉巡检"）
    String key;             // 安全 key（SanitizeTableKey）
    int rows;
    int columns;
    long updatedAtMs;
}

// CellHit.aidl —— 一次「说完了」的解析结果
package com.vta;
parcelable CellHit {
    int row;                // 0-indexed
    int column;             // 0-indexed
    String value;           // 归一后的字符串，如 "17.84"
    String raw;             // 原始 ASR 文本片段（"十七点八四"）
    long finalizedAtMs;
}
```

### 3.3 "单连接门卫" 在本地版的语义变化

现网是"全机一路语音连接"（`SherpaAsrBridge` 用 token 实现）。Native Service 改成 **per-app 一路**：

- 每个企业 App 连进来时给一个 `clientId`（在 AIDL bind 时拿）；
- `openSession` 时按 `clientId` 检查是否已有 session，**已有则 409**；
- 不同 App 可同时各开一路（每路消耗 ~1.2GB RAM + ASR 推理 CPU；普通平板撑不住"多路"，**【待定：限制 1 路，还是 N 路】**）。

### 3.4 partial/final/cells 三类事件

Native Service **不主动 push**。轮询模式：

- 企业 App 起线程，每 50~100ms 调一次 `getState(sessionId)` 拿 partial 文本做"识别中"提示；
- 端点触发后（Service 内部 `SilenceMs` 计时），完成 RaNER + 向量库命中，调 `pollCells` 拿到新 cells。
- 客户端拿到 `CellHit[]` 即完成一次"录入"。

## 5. 关键设计点

### 5.1 sherpa-onnx C++ 集成

- 编译：`sherpa-onnx` master（≥ 2025-12）已有官方 `aar` 和 cmake 集成。
- 加载：`dlopen("libsherpa-onnx.so")` + 调 `OnlineRecognizer`。
- 在线流：`OnlineStream` 接受 `AcceptWaveform(expected_sample_rate=16000, ...)`；循环 `IsEndpoint()` / `GetResult()` 拿 partial。
- 端点：`EndpointConfig.rule1.min_trailing_silence = 2.5`，与现网一致。
- HR：构造 `HomophoneReplacerConfig` 注入 lexicon / rule_fsts / rule_fars / hotwords_file；启动时一次性从 `assets/models/sherpa-onnx/hr/tables/<key>/` 加载。

### 5.2 GTCRN 降噪

- 现 `Asr/GtcrnDenoiser.cs` 的 STFT/ISTFT/状态缓存/overlap-add 逻辑**逐句翻译**到 C++。
- ONNX 推理走 **ONNX Runtime C++ API**（onnxruntime-android aar 提供）。
- session 启动时 `Reset()`，session 关闭时 `flush`（与现 .NET 实现一致）。

### 5.3 RaNER（BERT+CRF）C++ 实现

- ONNX Runtime C++ 跑 `model.onnx`。
- CRF 解码：照抄现 C# 代码 `Services/RaNerEngine.cs` 的 Viterbi（标签集 `O/B-SUB/I-SUB/B-OBJ/I-OBJ/B-VAL/I-VAL`）。
- `crf_transitions.json` 启动时一次性加载。

### 5.4 向量库 VTX1

- 二进制 VTX1 格式：768 维 float32，原子写（写 tmp → `rename()`）。直接用现 C# 写的格式，C++ 这边写一对一的 `vtx1_read / vtx1_write` 函数即可。
- 检索：内积（与现 `VectorIndex.cs` 一致）。表多到上万行时再上 HNSW；当前规模 6×6~10×20 暴力扫描够用。

### 5.5 HR 同音纠正 + 拼音表

- `相关文档/homophone/hr_char_pinyin.txt` 一行一字的拼音表。
- 现 C# `HomophoneReplacer.cs` 的 fuzzy match 逻辑（拼音近似 + 字符集过滤）逐句翻译。
- 数据小，启动时一次全载入内存。

### 5.6 session 编排

照搬现 `Asr/VoiceInteractionSession.cs`：
- 喂 PCM → 降噪 → sherpa partial/final → 同音纠正 → RaNER → 短语拼接 → 向量库检索 → 得 `CellHit`。
- 累计上限 `MaxChars=500`（同样可调）。
- 端点切句 2.5s（可调）。
- 切表：先 `closeSession` 再 `openSession(新表)`；与现网同约束。

### 5.7 内存与冷启动

- 冷启动：模型加载 ~8-10s（与现 .NET 网关首次 ASR 冷启动对齐）；可做"懒加载"——仅在 `openSession` 第一次被调时加载，给个 startup 进度 callback。
- 内存预算：8 GB 平板可以**同时**只跑一路（1.2-1.5 GB 工作集）；12-16 GB 平板可以**多路**（【待定：具体上限】）。
- 进程被系统杀：**offline 模式，进程死掉就完蛋**——不重连、不重试。Native Service 应注册 `START_STICKY` 让系统尽量复活。

## 6. 安全与权限

- `RECORD_AUDIO` 权限：**给企业 App**（AIDL 调起方），不在 Native Service 申请。
- 麦克风采集：在企业 App 端用 `AudioRecord` / `MediaRecorder` 拿 PCM → 16kHz float32 → 通过 AIDL `pushPcm` 喂给 Service。**Service 自己不采音**（更通用：某些企业 App 可能来自蓝牙耳机 / USB 麦克风 / 文件回放）。
- 文件存储：模型 / HR 表 / 表注册表全部放 app 私有目录 `getFilesDir()/vta/`，**不**放 sdcard（避免被其它 App 读）。
- 进程可见性：`<service android:exported="true">`（企业 App 跨进程调必须 true），但用自定义 permission `<permission android:name="com.vta.permission.BIND" android:protectionLevel="signature">` 锁调用方——**只有用同一签名签名的 App 才能 bind**，避免任意 App 调用。

## 8. 验证 / 验收

### 8.1 与现 .NET 网关对齐

- 同一段 PCM（用现 `selftest/denoise-test/inp_16k.wav` 或自录）→ .NET 网关 vs Native Service 输出比对 partial / cells。
- 同音纠正规则、HR 拼音表、RaNER 标签集 — **字级别一致**。
- VTX1 向量库：**二进制格式一致**——C++ 写的 .bin C# 能读、C# 写的 .bin C++ 能读（这点要专门写一个 round-trip 单测）。

### 8.2 离线稳定性

- 拔 WiFi、拔 SIM，连续 30 分钟语音 → cells 全部到位。
- 后台锁屏 10 分钟 → service 还在（不要求像前台那样 100% 活，能被系统杀时清理 + 重启即可）。
- 冷启动 ≤ 10s（模型已在 APK 内的前提下）。

### 8.3 多表 / 切表

- 同一 session 切表：必须先 close。
- 多表并发：8 GB 平板一路、12 GB 平板两路（**【待定】**）。
- 切表 ≤ 1s（含 RaNER / HR 资源热加载）。

### 8.4 异常路径

- 喂空 PCM 块：service 不崩。
- 喂错采样率（44.1kHz 等）：service 拒绝并返回明确错误码（**不是 panic**）。
- binder 断开：session 自动 close，资源回收。

## 9. 风险与未决项

### 9.1 已知技术风险

| 风险 | 缓解 |
|---|---|
| sherpa-onnx C++ 升级 / ABI 变动 | 锁 v1.12.x；自建一个 fork 长期维护 |
| ONNX Runtime ARM64 推理速度 | 已实测在 Cortex-A78 上 streaming-zipformer 实时性 OK；如出现回退降级到 14M mobile 模型 |
| APK 体积超 200 MB | 拆 AAB / OBB（按表拆 asset pack） |
| 后台 Service 被杀 | `START_STICKY` + foreground service（绑一个 0 像素的常驻通知，避免被 Doze 杀）|
| AIDL 跨进程传输大块 PCM 的开销 | 限制 `pushPcm` 单块 ≤ 4096 样本（256ms）；高频小块比低频大块更省 binder 事务 |

### 9.2 未决项（**必须跟集成方对齐**）

1. **【待定】接入什么企业 App**？签名 / 包名 / 调用方式（同步 / 异步 / 推送 / 轮询）。
2. **【待定】打包哪些表**？每张表都要在 Native Service 启动前就位，还是允许运行时 `importTable`？
3. **【待定】HR 规则 / 热词更新策略**？随 APK 升级，还是运行时热加载？
4. **【待定】多路并发上限**？8 GB 平板跑 1 路还是允许 2-3 路？
5. **【待定】是否复用现 .NET 端的部分能力**？例如：是否仍用现 .NET 网关做"远端管理后台"（HR 规则编辑、表导入、用户管理），Native Service 只跑识别？
6. **【待定】部署形态**？Native Service 单 APK 暴露 service 给任何用同签名的 App；还是把 service 内嵌到企业 App 内（同包同进程）？
7. **【待定】多语种**？当前只支持中文；如果客户有英文 / 方言需求，要不要在 Native Service 里同时跑多语种模型？

|---|---|---|
| **P0: Hello AIDL** | 空 Native Service，AIDL `health() / getVersion()` 跑通；企业 App 能 bind，能拿到 "ok" | 1 个工程师 + AAR 集成 1-2 周（首版） |
| **P1: ASR 流式打通** | `openSession` + `pushPcm` + `getState` 跑通；partial 文本与企业 App 显示一致 | P0 + 集成 sherpa-onnx C++ 1 周 |
| **P2: 端到端 cells** | `pollCells` 出 `CellHit[]`；同一段 PCM 在 .NET 网关 vs Native Service 输出**字级一致** | P1 + RaNER + 嵌入 + HR 翻译 |
| **P3: 多表 / 切表 / 单连接门卫** | 完整业务能力 | P2 |
| **P4: GTCRN 降噪** | 工厂场景落地（如果你要复用 GTCRN） | P2 + DSP 翻译 |

每一阶段都应**保留 P0~Pn 在 .NET 网关上的对照**——别一上来全切，留回退路径。
