# 语音输入表格填写智能辅助——测试报告

> 记录语音输入链路（语音 → 文本 → 三元组 → 表格坐标）的实现思路、部署初始化方式与测试方案，供验收与复测对照使用。
>
> **源码地址**：<https://github.com/kaisalife/voice-table-assist>
>
> 仓库**不含 models**；部署网关前在 `app/VoiceTableAssist/` 执行：
> `pip install modelscope && modelscope download --model yanxiashuiyun/VoiceTableAssist --local_dir .`

## 一、实现思路

### 1. 链路说明

整条链路分三步，各由一个模型接力：

| 步骤 | 模型 | 作用 | 输入 → 输出 |
|---|---|---|---|
| ① 听写 | ASR 语音识别（sherpa-onnx） | 把 16kHz 麦克风语音实时转成中文文字 | 语音 → 文字 |
| ② 拆分 | RaNER 命名实体识别 | 把句子拆成「主体 / 客体 / 值」 | 文字 → 三元组 |
| ③ 定位 | gte 向量检索 | 「主体 + 客体」拼成短语，在表格向量库中找最近的一条 | 三元组 → 表格坐标 |

最后服务下发 `{ row, column, value }`，前端回填对应单元格。

### 2. 示例

用户说「序号一，二号列，十七点八四」：

| 步骤 | 负责方 | 处理结果 |
|---|---|---|
| ① 听写 | ASR | 语音 → 「序号一，二号列，十七点八四」 |
| ② 拆分 | RaNER | 主体「序号一」+ 客体「二号列」+ 值「十七点八四」 |
| ③ 定位 | gte | 「序号一二号列」在向量库中匹配到 `(1, 2)` |

三个模型各司其职：ASR 只转文字；RaNER 拆句子；gte 把「行 + 列」拼成短语与向量库算相似度，最近的一条即坐标。

## 二、性能指标

### 1. 内存

| 阶段 | 内存 |
|---|---|
| 启动待机（模型未驻内存） | 约 120 MB |
| 使用中峰值 | 约 1.7 GB（网关约 1.0 GB + sherpa 子进程约 0.7 GB） |
| 空闲 180 秒后自动卸载 | 回落至约 120 MB |

### 2. 加载速度（首次使用冷启动）

| 动作 | 额外耗时 |
|---|---|
| 首次文本查询（RaNER + gte 引擎） | 约 1.5 ~ 2 s |
| 首次语音连接（含拉起 sherpa） | 约 8 ~ 10 s（期间前端收到 `loading` 帧） |

### 3. 磁盘

解压后约 2 GB（含三套 ONNX 模型与 sherpa 运行时），目标机无需安装 .NET（self-contained win-x64）。

## 三、部署初始化（导入表）

部署到新机器后，只需把「每张表的行标签 + 列数」交给服务，服务调用 embedding 模型为该表生成向量数据库。

原因：语音识别和 NER 与表无关，任意表可复用；只有 embedding 一步需要按表建向量库，以支持对该表的模糊匹配。

```json
POST /import_table
{
  "tableName": "力学性能",
  "columnCount": 8,
  "rows": [
    { "index": 1, "label": "外径" },
    { "index": 2, "label": "屈服强度" }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `tableName` | 表名；缺省时用 `default` 表 |
| `columnCount` | 列数（1 起） |
| `rows[].index` | 行号（从 1 开始） |
| `rows[].label` | 行标签，即检验内容，如「外径」 |

成功返回 `{ status:"ok", rowsCount, colsCount, entries, dim }`。`entries` 为生成的向量条数，`dim` 固定 768（gte-base-zh）。

## 四、已实现功能

### 1. 用户体验角度

1. **一键填表**：开麦说话，停顿约 2.5 秒自动回填；一句话可同时填多个格子。
2. **前端极简**：前端只负责开关麦克风、收 `loading / ready / partial / final / cells / error` 事件并回填，不做文本合并、静默判定、解析。
3. **说法灵活**：行说「序号一 / 第一行 / 外径」、列说「二号 / 第二个 / 测量值几」都指同一格；换表只需重新 `POST /import_table` 初始化向量库，三个模型全部复用。
4. **资源自动管理**：冷启动发 `loading` 进度、空闲自动卸载。

### 2. 落地细节

1. **先连 WS 再弹麦克风权限**（`voice-mic.js`）：懒加载与权限弹窗并行。
2. **服务端判定说完**：sherpa 关闭自动切句（`--enable-endpoint=false`），服务端每次 `final` 重布防 2.5s 静默计时；中途自然停顿会继续累计（`MergeText` 去重拼接），话真停住才整句解析。
3. **边缘兜底**：
   - 累计超 `Interaction:MaxChars`（默认 120）发 `ACCUM_OVERFLOW` 并清空；
   - 解析失败发 `PARSE_FAILED`。
   > 原因：RaNER 最多接收 510 字符，但过长输入会降低推理精度与速度，建议定期清理，超 120 字符自动退出。
4. **同音纠正**：放在 ASR 之后、NER 之前（拼音→字、付→负、实→十）。

## 五、泛化性说明

本方案不靠规则/字典硬匹配，而是靠模型泛化到「没教过 / 没生成过」的表达，分三层验证：

### 1. RaNER 对未教句子的拆分

- 代码支撑：`TripleExtractor` 对任意 BIO 序列做「SUB 为起点、其后邻接 OBJ+VAL」的结构化拆解，不依赖固定槽位、无模板匹配。
- 结论：按「检验内容开头 + 测量值几 / 几号 / 第几个」的句式，拆分有保证。

### 2. gte 对未生成说法的命中（核心）

| 项 | 说明 |
|---|---|
| 风险点 | 导入时 `CellPhraseGenerator` 只把有限几种说法编成向量，若 gte 只「背」，换说法就查不到 |
| 泛化依据 | gte-base-zh 语义向量 + 余弦最近邻，对「词面不同、语义相同」的新说法按语义近似命中 |
| 边界 | 说法越接近训练见过的组合，置信越高；句子越拗口、冗余越多、词序越乱，越可能掉回相邻坐标 |

### 3. 换表与数值

| 项 | 说明 |
|---|---|
| 换表 | ASR、RaNER 与表无关、全表共用；只有 gte 索引按表建。换表只需重新 `import_table`，三模型零改动 |
| 数值 | `ChineseNumeral` 用正则 + 进位累加转阿拉伯，支持「零六 / 一十二点五 / 整十 / 点后两位」，超 1000 归零 |

## 六、测试方案

### 1. 测试用例设计

生产模板表（6×6：外径 / 内径 / 表面光洁度 / 硬度 / 直线度 / 圆度），每种用法一条用例，预期坐标取指南《测试用例》已给结果：

| # | 指南用法 | 用例输入（照指南原句） | 预期 row,column,values | 目的 |
|---|---|---|---|---|
| 1 | 逐行填·X号/第几个 | 硬度（这个是检验内容），一号是五十点零，二号是四十九点九九，三号是五十一点五，四号是六十点七五，五号是六十六点七五，六号是四十八点七七 | row=4：col1=50, col2=49.99, col3=51.5, col4=60.75, col5=66.75, col6=48.77 | 基础链路 + 一行填满 |
| 2 | 逐行填·测量值 | 硬度，测量值一是五十点零，…，测量值六，四十八点七七 | 同 #1（row=4） | 助词变化 + 省略「是」 |
| 3 | 逐列填 | 第一列，硬度填十，圆度是五十 | (4,1)=10, (6,1)=50 | 先列后行的顺序 |
| 4 | 助词灵活 | 硬度，测量值二填49.99，三改为51.5，四为60.75，五八十 | 同 #1（row=4） | 填 / 改为 / 为 / 无助词 |
| 5 | 跳位填入 | 硬度，一号是五十，三号是二十 | (4,1)=50, (4,3)=20 | 不必连续、可跳 |
| 6 | 单值修改 | 硬度，二号是十 | (4,2)=10 | 只改一个格 |

复测要求（验证同一套用法换表、换数值仍成立）：

1. **换表复测**：把 6 条换到一张新表（不同行标签 / 列数）重跑。
2. **换值复测**：同一批句子把数值换成「一十二点五 / 零六 / 99.99 / 超一千」等。

### 2. 测试方法

1. 用 `POST /text_to_json`（纯文本）逐条喂，先绕开 ASR 误差，让「拆 / 定位 / 转数值」三层可分别定位。
2. 每条导出结果表：输入 → 实际返回 → 与预期比对 → 命中 / 失败。
3. HTTP 全过后，再挑几条走语音入口作端到端附加验证（此时引入 ASR 与同音纠错，单独记录，不并入纯文本统计）。
4. 同一机器、同一份模型、同一张表固定复测，保证结果可复现。

### 3. 结果评判

| 项 | 规则 |
|---|---|
| 单条判据 | `row / column / values` 三者全对 = 命中；任一项错、返回空、坐标 ≤ 0、值为 0 都算失败 |
| 分组统计 | 先看 6 条真实用法全过（链路无误），再看「换表」「换数值」两组复测命中率，定位最弱环节 |
| 错误归因 | 分三类：拆错（RaNER）、定位错（gte）、数值错（ChineseNumeral），占比最高的一类即生产阶段最该补的层 |
