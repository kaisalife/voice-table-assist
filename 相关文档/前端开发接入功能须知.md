# 语音填表前端接入须知——生产车间平板 H5

> 依据《api文档.md》与 `wwwroot/voice-mic.js`、`wwwroot/index.html` 现有实现整理，供前端开发与联调使用。
>
> **源码地址**：<https://github.com/kaisalife/voice-table-assist>
>
> GitHub 仓库**不含 models**；部署网关前需在 `app/VoiceTableAssist/` 下执行：
> `pip install modelscope ; modelscope download --model yanxiashuiyun/VoiceTableAssist --local_dir .`

## 一、总体方案

后端为 Windows 上部署的单进程服务（默认端口 `15232`），语音识别、文本合并、自动提交、语义解析全部在服务端完成。前端只做两件事：**开关麦克风、收结果填表**。

```
平板 H5（按钮 + 表格）
   │  引入网关托管的 voice-mic.js（一个 script 标签）
   │  WebSocket 上行 PCM 音频，下行 cells 结果
   ▼
VoiceTableAssist 网关（Windows 服务 :15232）
   └─ sherpa 流式 ASR + RaNER 语义解析 → [{row, column, values}]
```

三种接入形态：

| 形态 | 适用场景 | 前端工作量 | 备注 |
|---|---|---|---|
| 网关托管验证页 | 演示、验收 | 零 | 浏览器打开 `http://<网关IP>:15232/` |
| **自有 H5 引脚本（推荐）** | 车间业务页面集成 | 约 20 行 | 本文第二、三章 |
| Cordova 安卓壳 | 平板经局域网 IP 访问 | 复用同一套代码 | 见第六章，解决 HTTP 麦克风限制 |

**核心原则**：不要自己实现 WebSocket 与音频采集，直接复用网关托管的 `/voice-mic.js`。该脚本无 UI、无依赖，跨源可用。

## 二、三分钟接入（整页复制即用）

把下面内容存为 `voice-demo.html`，替换 `BASE` 为网关地址，平板浏览器打开即可说话测试。

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>语音填表最小示例</title>
</head>
<body>
  <!-- 1. 语音按钮：唯一交互入口 -->
  <button id="voiceBtn" onclick="mic.toggle()">开始语音录入</button>
  <span id="state">（点击后请授权麦克风）</span>
  <div id="live"></div>

  <!-- 2. 业务表格：按 data-row / data-col 标好行列号。此处行列号与规范坐标一致（偏移 0）；若页面带表头/序号列，见第四章「前端偏移量设计」 -->
  <table border="1">
    <tr><th>项目</th><th>1号</th><th>2号</th></tr>
    <tr><td>水位</td><td data-row="1" data-col="1">—</td><td data-row="1" data-col="2">—</td></tr>
    <tr><td>汽压</td><td data-row="2" data-col="1">—</td><td data-row="2" data-col="2">—</td></tr>
  </table>

  <!-- 3. 引入网关脚本，创建实例 -->
  <script src="http://192.168.1.100:15232/voice-mic.js"></script>
  <script>
    const mic = VoiceMic.create({
      base: 'http://192.168.1.100:15232',  // 网关地址
      table: '锅炉巡检',                    // 表名；省略 = 当前活动表
      onResult: fillCells,                  // 说完停顿约 2 秒自动到达
      onError: (msg) => document.getElementById('state').textContent = '错误：' + msg,
      onStateChange: (s) => {
        const btn = document.getElementById('voiceBtn')
        if (s.state === 'ready') {
          btn.textContent = '■ 结束录音'
          document.getElementById('state').textContent = '录音中：说完停顿约 2 秒自动提交'
        } else if (s.state === 'closed' || s.state === 'stopped') {
          btn.textContent = '▶ 开始语音录入'
        }
      },
    })

    // 唯一的业务代码：把结果写进自己的表格
    function fillCells(cells, text) {
      document.getElementById('live').textContent = '本次识别：' + text
      for (const c of cells) {
        const td = document.querySelector(
          `td[data-row="${c.row}"][data-col="${c.column}"]`)
        if (td) td.textContent = c.values   // values 已是阿拉伯数字
      }
    }
  </script>
</body>
</html>
```

接入要点：

| 步骤 | 动作 | 说明 |
|---|---|---|
| 1 | `<script>` 引 `/voice-mic.js` | 从网关地址跨源加载，网关已配 CORS |
| 2 | `VoiceMic.create({...})` | 参数见第三章 |
| 3 | 按钮调 `mic.toggle()` | 开/关切换；也可用 `start()`/`stop()`/`cancel()` |
| 4 | `onResult` 里填自己的表格 | 这是唯一需要写的业务代码 |

## 三、VoiceMic API 速查

### 1. `VoiceMic.create(options)` 参数

| 参数 | 必填 | 默认值 | 说明 |
|---|---|---|---|
| `base` | 否 | 当前页面 origin | 网关地址，如 `http://192.168.1.100:15232` |
| `table` | 否 | 当前活动表 | 表名；连接即激活该表，同音纠正规则随表生效 |
| `workletUrl` | 否 | `base` 下 `audio-capture-worklet.js` | 采集脚本地址，一般不用传 |
| `readyTimeoutMs` | 否 | `30000` | 点击→可说话的总超时（含权限等待、模型冷启动） |
| `onResult(cells, text)` | 建议 | 空函数 | **业务核心回调**：解析结果与原文 |
| `onError(message)` | 建议 | 空函数 | 错误提示（含超时、409、权限等） |
| `onStateChange({state, message})` | 建议 | 空函数 | 驱动按钮状态，见下表 |
| `onTranscript(text, isFinal, accumulated)` | 否 | 不启用 | 实时识别文本展示 |
| `onLevel(rms)` | 否 | 不启用 | 麦克风输入电平（0~1），可做音量条/无声检测 |
| `onDiagnostics({ctxState, rate, blocks})` | 否 | 不启用 | 采集链路诊断，排障用 |

### 2. 实例方法

| 方法 | 说明 |
|---|---|
| `toggle()` | 开/关切换；按钮唯一调用点，返回 Promise |
| `start()` | 开启（连接 WS → 弹权限 → 采集） |
| `stop()` | 结束并立即提交累计文本 |
| `cancel()` | 取消（清理全部资源，权限弹窗悬着也能安全作废） |
| `active` | 只读属性，是否录音中 |

### 3. `onStateChange` 状态机

| state | 含义 | 建议界面 |
|---|---|---|
| `connecting` | 连接中（可能等权限弹窗） | 按钮置「连接中，点击取消」 |
| `loading` | 服务端模型冷加载（`message` 为进度文案） | 同上，展示 `message` |
| `connected` | WS 已通，等待 `ready` | 保持连接中 |
| `ready` | 可以说话 | 按钮置「结束录音」 |
| `closed` | 连接关闭 | 回到空闲态 |
| `stopped` | 会话已结束并清理 | 回到空闲态 |

## 四、结果数据与填表规则

### 1. `cells` 结构

```json
[ { "row": 1, "column": 2, "values": 50.5 } ]
```

| 字段 | 说明 |
|---|---|
| `row` / `column` | **规范坐标**，从 1 开始：`row`=行标签在导入 `rows` 数组中的序号（第一个行标签=1），`column`=列序号（第一列=1）。与前端页面 UI 布局无关，填表时按本表固定偏移换算（见下文「前端偏移量设计」） |
| `values` | 阿拉伯数字（`double`）；服务端已把中文数字转好，含负数（「负九十五」→ -95） |

### 2. 填表规则（已由服务端保证）

| 规则 | 对前端的含义 |
|---|---|
| 无法定位单元格的条目已被过滤 | 收到的 `cells` 一般都可命中；仍建议判空 |
| 重复格子以新值覆盖 | 同一句话里多次提到同一格，以最后一次为准 |
| 一次提交可含多格 | 「硬度一号是五十，二号是四十九点九九」返回 2 个 cell |
| 未命中时 `cells` 为空数组 | 界面可提示「未识别到有效数据」 |

### 3. 前端偏移量设计（规范坐标 → 页面坐标）

#### 3.1 什么是规范坐标

服务端返回的 `row` / `column` 是**表结构坐标**，只由导入时的表定义决定，与前端页面的 HTML 布局完全解耦：

| 坐标 | 定义 |
|---|---|
| `row` | 行标签在导入 `rows` 数组中的序号，**1 基**：第一个行标签 = 1，第二个 = 2，…… 第 N 个 = N |
| `column` | 列序号，**1 基**：第一列 = 1，…… 第 `columnCount` 列 = `columnCount` |

后端**不知道也不关心**你的页面表格里第 1 行是不是表头、左边有没有序号列、单元格编号从几开始。无论谁调用、无论页面怎么画，返回的永远是这套规范坐标。

#### 3.2 为什么要偏移

前端页面里的表格常常和规范坐标对不齐，例如：

- 页面 `<table>` 第 1 行是表头（「项目 / 1号 / 2号 / …」），真正的数据行从第 2 行开始；
- 页面表格最左列是序号列（1、2、3…），真正的数据列从第 2 列开始；
- 页面行列编号从 0 开始，或数据区中间插了合计行/分隔行。

这些差异全部由**前端用一张固定偏移**消化，后端零改动。

#### 3.3 换算公式与实现

```
uiRow = cell.row    + rowOffset
uiCol = cell.column + colOffset
```

- `rowOffset` / `colOffset`：**每张表一个固定值**（不是运行时动态计算），规范坐标与页面坐标一致时填 0。
- 不同表的偏移可以不同（A 表带表头 `rowOffset=1`，B 表不带 `rowOffset=0`），单张表确定后保持不变。
- **越界判断一律用规范坐标范围**（`1 ≤ row ≤ 行数`、`1 ≤ column ≤ 列数`），先校验再加偏移查找单元格，避免偏移后误判。

示例（页面表格带一行表头 + 一列序号）：

```javascript
const TABLES = {
  '锅炉巡检': {
    rows: ['水位', '汽压', '汽温', '风压', '流量', '给水温度'],
    columnCount: 4,
    rowOffset: 1,   // 页面第 1 行是表头，数据行从第 2 行开始
    colOffset: 1,   // 页面第 1 列是序号列，数据列从第 2 列开始
  },
}

function fillCells(cells, text) {
  const t = TABLES[currentTableName]
  for (const c of cells) {
    // 1) 先按规范坐标范围校验（与偏移无关）
    if (c.row < 1 || c.row > t.rows.length || c.column < 1 || c.column > t.columnCount) continue
    // 2) 再加本表固定偏移，换算成页面坐标
    const uiRow = c.row + t.rowOffset
    const uiCol = c.column + t.colOffset
    const td = document.querySelector(`td[data-row="${uiRow}"][data-col="${uiCol}"]`)
    if (td) td.textContent = c.values
  }
}
```

对照关系（示例偏移 `rowOffset=1, colOffset=1`）：

| 规范坐标 | 页面坐标 | 落点 |
|---|---|---|
| `(1, 1)` 第一个行标签 × 第一列 | `(2, 2)` | 数据区左上角 |
| `(2, 3)` 第二个行标签 × 第三列 | `(3, 4)` | 第二数据行 × 第三数据列 |

### 4. 说话方式（写给车间操作工）

| 说 | 效果 |
|---|---|
| 「水位一号五十点零」 | 命中 `row=水位, column=1` |
| 「二号六十」 | 紧接上句，沿用同行的列定位（累计文本保留上下文） |
| 说完**停顿约 2 秒** | 自动提交；或点按钮「结束录音」立即提交 |
| 累计超 500 字 | 服务端清空并断开，重新点按钮即可 |

## 五、表初始化（前端可复制）

页面打开时检查表是否已导入，未导入自动导入，已存在则刷新语音热词。**整段复制即用**：

```javascript
const TABLES = [
  { name: '锅炉巡检', rows: ['水位', '汽压', '汽温', '风压', '流量', '给水温度'], columnCount: 4 },
]

async function fetchJson(url, opts) {
  const res = await fetch(url, opts)
  const body = await res.json().catch(() => null)
  if (!res.ok) throw new Error(`HTTP ${res.status} ${body?.error || ''}`)
  return body
}

async function initTables(base) {
  const list = await fetchJson(`${base}/tables`)
  for (const t of TABLES) {
    if (!(list.tables || []).some(x => x.name === t.name)) {
      await fetchJson(`${base}/import_table`, {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({
          tableName: t.name,
          // index 已弃用：后端忽略它，一律按 rows 数组顺序编号（第一个行标签=1），与页面 UI 无关
          rows: t.rows.map(label => ({ label })),
          columnCount: t.columnCount,
        }),
      })
    } else {
      await fetchJson(`${base}/api/table/voice`, {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ rows: t.rows, columnCount: t.columnCount, tableKey: t.name }),
      }).catch(() => {})   // 刷新失败可忽略
    }
  }
}
```

| 要点 | 说明 |
|---|---|
| 行标签 | 2~4 个汉字为宜，避免生僻字与同音混淆 |
| `columnCount` | 列数；无需传列名，列定位全靠列号 |
| `index` 字段 | 已弃用；后端忽略它，行号 = 行标签在 `rows` 数组中的顺序（第一个=1） |
| 重复导入 | 覆盖旧表（last-write-wins），向量库重建 |
| 建议调用时机 | 页面加载时自动跑一次；导入失败给出重试入口 |

## 六、部署形态与安全上下文（必读）

浏览器只在**安全上下文**（HTTPS 或 localhost）开放麦克风 API。平板经局域网 IP 用 `http://` 打开页面时麦克风会被浏览器禁用——这是浏览器限制，不是服务问题。

| 部署形态 | 麦克风可用性 | 说明 |
|---|---|---|
| **网关 HTTPS（推荐）** | 可用 | 网关机运行 `make-cert.bat` 后监听 `https://<网关IP>:15433/`；平板安装一次 `certs\ca.crt` 即为安全上下文。机制详见部署文档「1.1 HTTPS 证书机制」 |
| 平板浏览器 + `http://<IP>:15232` | **不可用** | 无授权弹窗，`getUserMedia` 直接失败 |
| Cordova 安卓壳（备选） | 可用 | 壳内 origin 为 `http://localhost`，属安全上下文；`cordova/build.ps1` 打包；需维护 Node/Android SDK 工具链 |
| Chrome/Edge 开发期例外 | 可用（仅调试） | `chrome://flags/#unsafely-treat-insecure-origin-as-secure` 加入网关地址，仅开发机使用 |

Cordova 壳接入差异只有一点：壳内页面与网关不同源，`base` 必须显式填局域网地址（可存 `localStorage` 让操作工免输入）：

```javascript
const mic = VoiceMic.create({
  base: localStorage.getItem('vt-gateway') || 'http://192.168.1.100:15232',
  table: '锅炉巡检',
  workletUrl: './audio-capture-worklet.js',   // 与壳内页面同源加载
  onResult: fillCells,
})
```

## 七、联调与排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 点按钮无反应/报「不支持麦克风」 | HTTP + IP 访问，非安全上下文 | 见第六章：网关开 HTTPS（make-cert.bat）后走 `https://<IP>:15433/` |
| 权限弹窗不再出现 | 之前点过「阻止」 | 地址栏左侧图标 → 网站设置 → 麦克风改「允许」 |
| 报「已有一路语音会话」 | 服务端单连接限制 | 先结束上一路（或刷新上一页面）再开 |
| 电平条不动、识别无结果 | 系统未授权应用/输入设备选错/静音 | Windows「设置→隐私→麦克风」放行；检查默认输入设备 |
| 安卓壳内报 `NotReadableError` | 权限已给但麦克风起不来：被其他应用独占（对讲/录音类 app），或 ROM 音频路由问题 | 关掉占用麦克风的后台应用重试；APK 须含 `MODIFY_AUDIO_SETTINGS` 清单权限（壳内 config.xml 已配） |
| 安卓壳内报 `PermissionDeniedError` | 运行时权限被拒绝 | 系统设置 → 应用 → 语音巡检 → 权限 → 麦克风改「允许」 |
| 报「连接语音后端超时」 | 服务未启动或冷启动超 30s | `GET /api/health` 确认服务在线后重试 |
| `ACCUM_OVERFLOW` 错误后自动断开 | 累计文本超 500 字 | 正常保护；重新点按钮继续 |
| 命中行列不对 | 说话方式或表定义不匹配 | 核对行标签读音；参考第四章说话方式 |
| 切表后识别仍用旧表热词 | 录音中切表被禁止 | 先结束录音再切；连接带 `table` 参数即随连接生效 |

联调工具：

| 工具 | 用途 |
|---|---|
| `GET /api/health` | 服务在线、当前活动表 |
| `GET /tables` | 已导入表清单 |
| 网关首页 `http://<IP>:15232/` | 完整验证页，含电平条、日志、诊断 |

## 八、上线检查清单

1. **后端可达**：平板能打开 `http://<网关IP>:15232/api/health`。
2. **部署形态**：Cordova 壳或 HTTPS，不用裸 HTTP+IP 上生产。
3. **表已初始化**：`GET /tables` 能看到业务表，或页面已跑 `initTables`。
4. **麦克风授权**：壳/浏览器首次运行已点「允许」，且未被记住为「阻止」。
5. **单连接约束**：业务页面不会有并行开麦的入口。
6. **`onResult` 边界**：空数组、越界行列均已判空。
7. **错误提示**：`onError` 与 `onStateChange` 的超时/409 文案已落到界面。

## 末、存疑点

1. 生产网络是否允许平板与网关之间的 WebSocket 长连接（防火墙/网闸策略需确认）？
2. Cordova 壳的 `base` 由操作工手输还是随 APK 内置固定值？
3. HTTPS 形态下证书来源（企业内网 CA 还是自签名并逐台信任）是否已定？
4. `onTranscript` 的累计文本是否需要在业务页面向操作工展示以核对录入内容？
5. 一台平板是否会同时开多个业务页签（单连接限制下第二个页签将连不上）？
