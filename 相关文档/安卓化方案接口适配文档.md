# 安卓化方案接口适配文档（C#+H5 主应用接入 VTA 语音表格插件）

> **读者**：主应用（C# .NET8 + H5/npm 混合）客户端组、VTA 插件组。
> **硬约束**：主应用团队**只有 .NET8 + npm 环境，没有任何 Android 构建工具链**——接入过程
> 不允许出现 AIDL 编译 / AAR 绑定 / NDK / gradle 等任何需要 Android 工具链的步骤。
> **结论**：采用**进程内直调（C ABI + DllImport）**——插件组交付 `libvta-service.so` + `VtaNative.cs`
> + 模型资产，主应用零工具链、零进程间通信，函数调用即接入。
> **配套**：`安卓化方案/README.md`（§3.5 WS↔内核映射）、`新语音输入同音解决方案.md`（纠错机制）。
> **版本**：接口 v1（`vta_version()==1`）。

## 一、角色与边界

```
┌─ 主应用进程（C#+H5，一个 APK）────────────────────────────┐
│ H5 页面(WebView)                                          │
│  表格 UI / 麦克风按钮 / 状态与回填                          │
│   ↕ WebView 桥(消息 JSON)                                  │
│ C# 宿主（VtaNative.cs → DllImport libvta-service.so）      │
│  ├ 引擎（进程内）：ASR/降噪/RaNER/向量检索                  │
│  ├ 采音（AAudio，RECORD_AUDIO 在主应用）                    │
│  └ 每表向量索引 + 每表热词（随会话绑定当前表）               │
│ 模型资产（int8 ≈360MB）随主应用 APK 分发                    │
└───────────────────────────────────────────────────────────┘
```

- **H5 只做 UI**：不接触音频与原生调用；通过 WebView 桥把"用户意图"（导表/开始/停止）与
  "表格结构"（`{name, rows[], cols}`）交给 C#，把"状态/partial/cells"渲染出来。
- **C# 宿主**：DllImport 直调插件引擎 + 会话生命周期 + H5 消息路由。
- **无跨进程**：引擎在主应用进程内（`VtaTestActivity` 测试页即此形态，已长期实测）。
  代价与缓解见 §八；需要进程隔离/独立升级时，回退到"独立插件 APK"形态（AIDL，备选未选）。

## 二、交付物（VTA 组 → 主应用组）

| 交付物 | 说明 |
|---|---|
| `libvta-service.so`（arm64-v8a / x86_64） | 引擎 + C ABI 导出（§三） |
| `VtaNative.cs` | 单文件 .NET8 DllImport 客户端（含 `VtaClient` 高层封装），纯 BCL 无第三方依赖 |
| 模型资产 `models/**`（int8 全套 ≈360MB） | 随主应用 APK 的 `AndroidAsset` 分发；或首跑从企业内网下载（见 §七 风险） |
| 本文档 | 契约 + 接入步骤 + 验收 |

主应用侧**唯一构建相关改动**：`.csproj` 增加 `AndroidNativeLibrary`/`AndroidAsset` 条目与
`RECORD_AUDIO` 权限——改工程文件，不需要任何 Android 工具链。

## 三、C ABI 契约（vta_c_api.h，全部 UTF-8）

| 函数 | 说明 | 返回 |
|---|---|---|
| `int vta_start(const char* dataDir)` | 初始化引擎。dataDir=模型根目录（主应用先把 assets 的 models/** 复制到 filesDir/vta）。幂等 | 0/-2/-4 |
| `int vta_version()` | 协议版本（当前 1） | 1 |
| `int vta_health(char* out, int cap)` | `"ok"/"loading:…"/"error:…"/"not_started"` | 0；cap 不足返回所需长度 |
| `int vta_list_tables(char* out, int cap)` | JSON 数组 `[{name,key,rows,columns,updatedAtMs}]` | 同上 |
| `int vta_import(name, rowsText, cols)` | 导入表；`rowsText`=行标签每行一个（`\n` 分隔）；同步建索引落盘；幂等（同名覆盖） | 0/-2/-3/-4 |
| `int vta_open(table, silenceMs, captureMode)` | 打开**唯一**会话；已有活动会话先自动关闭（含静默提交）。captureMode：0=引擎自采音（**推荐**）/ 1=主应用 `vta_push_pcm` 喂流；`silenceMs≤0` 取默认 300ms | sessionId>0 / -2 / -3 |
| `int vta_push_pcm(sid, const float*, n)` | captureMode=1：16kHz float32 单声道，n≤4096 | 0/-2 |
| `int vta_state(sid, out, cap)` | JSON `{sessionId,tableName,phase,partial,lastPartialMs}`；`phase ∈ idle/listening/endpointing/closed`；**partial 已过全部纠错** | 0 |
| `int vta_cells(sid, maxN, out, cap)` | JSON 数组 `[{row,column,value,raw,finalizedAtMs}]`，**0-indexed**；有货即返、无货挂 ≤250ms（禁 UI 线程） | 0 |
| `int vta_close(sid)` | flush + fold partial + 提交剩余 cells；关闭后的最后一批 cells 仍可 `vta_cells` 取一次 | 0/-2 |
| `int vta_set_denoise(int on)` | 降噪开关，对新会话生效 | 0 |
| `void vta_shutdown()` | 释放全部会话与引擎（进程退出前可选） | — |

缓冲区约定：`out/cap` 由调用方提供；内容不足时**截断写入并返回所需长度**（>0 表示需扩容重试）。

### 行为要点

- **单会话**：一个物理麦克风 = 同一时刻至多一路识别。`vta_open` 幂等（关旧开新），换表即换会话。
- **每表隔离**：行标签热词、向量索引为该表快照（与 H5 表格结构一一对应）；位置词按列数枚举。
- **懒加载**：`vta_start` 后引擎按需装载；`vta_health` 观察进度。
- **失败模式**：读音差太远或表内两行音近 → 放弃不填（宁缺勿错，不猜测）。

### 坐标换算（常见错误，必读）

`vta_cells` 返回的 `row/column` 是**「导入清单」的坐标**，不是真实页面表格的坐标：

- `row = 0` 表示 `vta_import` 时 `rows_text` 的**第 1 个行标签**；`column = 0` 表示该表的**第 1 个数据列**。
- 真实表格通常在数据区之外还有**表头行、单位行**，行标签列左侧还有**序号列**等——
  直接拿 `(0,0)` 回填，值会落到表头/错列上。

**换算公式**（0-indexed；最终 1-based 显示各 +1）：

```
实际行 = rowOffset + row      # rowOffset = 导入清单第 1 行标签上方的行数（表头/单位行）
实际列 = colOffset + column   # colOffset = 行标签列左侧的列数（序号列等）
```

**前提**：`rows_text` 中行标签的顺序必须与真实表格中这些行的出现顺序**一致**
（真实表里不需要语音填写的行，不要写进清单，保持剩余行的相对顺序即可）。

**责任划分（二选一，不要两边都算）**：
- **推荐：C# 侧换算**——H5 在 `vta.importTable` 消息里把 `rowOffset/colOffset` 一并传给 C#，
  C# 推送 `vta.cells` 前完成换算，H5 拿到的就是可直接回填的实际表格坐标；
- 或 H5 侧换算——C# 透传原始坐标，H5 按自己的表格布局加偏移。

**反例**：一张「2 行表头 + 第 1 列为序号列」的表，未换算时 `row=0,column=0` 的值会填进**表头行**——
这是集成联调阶段最常见的错误，§七 有专项用例。

## 四、C# 侧接入（`VtaNative.cs`）

### 4.1 工程改动（.csproj）

```xml
<ItemGroup>
  <AndroidNativeLibrary Include="libs\arm64-v8a\libvta-service.so" />
  <AndroidNativeLibrary Include="libs\x86_64\libvta-service.so" />
  <AndroidAsset Include="assets\models\**\*" />
</ItemGroup>
<uses-permission android:name="android.permission.RECORD_AUDIO" />  <!-- Manifest -->
```

### 4.2 模型解压 + 初始化（首次启动一次）

```csharp
// 把 assets 的 models/** 复制到 filesDir/vta（保持目录结构），然后：
var client = new VtaClient();
client.Start(Path.Combine(FileSystem.AppDataDirectory, "vta"));
```

### 4.3 会话流程

```
导入表:   client.ImportTable("锅炉巡检", new[]{"水位","汽压","汽温","风压","流量","给水温度"}, 4)
开始录入:  int sid = client.Open("锅炉巡检", 300, 0);   // 插件 AAudio 自采音
收流:      后台 Task：
             每 50~100ms  PollState(sid) → partial 变化 → 推 H5（vta.state）
             每 ~200ms    PollCells(sid, 16) → 非空 → 推 H5（vta.cells）→ 回填单元格
用户点停止: client.Close(sid) → 再 PollCells 一次拿最后一批
页面退出:   （可选）client.Dispose() → vta_shutdown
```

- `RECORD_AUDIO` 运行时授权由主应用申请（一次）。
- `PollCells` 禁止 UI 线程调用。

## 五、H5 ↔ C# 桥（两种，二选一）

**方案 a（推荐）：WebView 消息桥**（`WebView.AddJavascriptInterface` 或 hybrid 现有桥）：

H5 → C#（`window.VtaBridge.post(json)`）：

| type | 载荷 | 对应 C# |
|---|---|---|
| `vta.importTable` | `{name, rows:[…], cols:n, rowOffset, colOffset}` | `ImportTable`（偏移随消息登记，见 §3.4 坐标换算） |
| `vta.open` | `{table?, silenceMs?}` | `Open` |
| `vta.stop` | `{}` | `Close` |
| `vta.denoise` | `{on:bool}` | `SetDenoise` |
| `vta.health` | `{}` | `Start`/health |

C# → H5（`webView.EvaluateJsAsync("window.dispatchEvent(new MessageEvent('vta',{data:"+json+"}))")`）：

| type | 载荷 | 说明 |
|---|---|---|
| `vta.state` | `{phase, partial}` | 实时刷新"正在听…" |
| `vta.cells` | `{cells:[{row,col,value,raw}]}` | **row/col 已按登记的偏移换算成实际表格 0-indexed 坐标，H5 直接回填** |
| `vta.error` | `{code, msg}` | -2/-3/-4 的用户文案映射 |
| `vta.ready` | `{version}` | 引擎就绪 |

**方案 b（零改动复用现网 H5）**：现网 H5 的表格语音页按 WS 协议对接 .NET 网关（`?table=`、
二进制 PCM 帧、`partial/final/cells`、`{"type":"stop"}`）。C# 宿主起一个回环 WS 并逐行实现
现网 WS↔C ABI 映射（`安卓化方案/README.md` §3.5 表），H5 客户端原样接入。

## 六、安全与权限

| 项 | 措施 |
|---|---|
| 麦克风 | 主应用 Manifest 声明 + 运行时授权（用户点"开始录入"时申请） |
| 模型保护 | 模型随主应用 APK（企业内部分发），不落公共存储 |
| 崩溃上报 | 引擎与主应用共进程：接入方需带 native 崩溃捕获（如 Breakpad/xcrash），崩溃日志回传 VTA 组 |

## 七、联调与验收清单

| 用例 | 预期 |
|---|---|
| `ImportTable(6行4列)` → `Open` → 说「水围一号五米」 | partial=`水位一号五米`；Close 后 cells 含 {row:0,col:0,value:"5"}（导入清单坐标） |
| 登记偏移 rowOffset=2、colOffset=1（2 行表头 + 行标签列前 1 列） | 推给 H5 的 `vta.cells` 中同一结果坐标变为 {row:2,col:1}（实际表格坐标），前端直接回填 |
| 「胀差二号一点二」（缺字行） | cells 含 {row:3,col:1,value:"1.2"}（热词数字去十 + 吸附） |
| 「硬度一号是十七点八四二号测量值六十」 | cells 含 (0,0)=17.84、(1,1)=60 |
| 重复 `Open` 同表 | 幂等：关旧开新，返回新 sessionId |
| `Start` 未解压模型 | -4/-3，`vta_health` 提示 |
| 主应用杀进程（会话未关） | 进程一起退出（共进程），无残留 |
| captureMode=1：喂 4 秒 f32 | 同 captureMode=0 结果 |

**设备实测**：`--capi` 冒烟（走 C ABI 全链路：start→import→open→push→state→cells→close→drained）
已在 MuMu x86_64 通过——`印度→硬度`（吸附 0.95）→ cell(0,0)=17.84、(1,1)=0，与 AIDL 路线一致。

## 八、风险与缓解

| 风险 | 缓解 |
|---|---|
| 引擎崩溃连带主应用 | 共进程固有代价；引擎已长期实测稳定 + 主应用接入崩溃捕获回传 |
| 主 APK +360MB | int8 全套；可选"首跑从企业内网下载模型包"（`vta_start` 前解压到位即可） |
| 引擎/模型升级需主应用发版 | 模型与引擎分离为"模型包"（首跑下载/MDM 推送），引擎变更频率低 |
| 首次懒加载数秒 | 主应用启动预热 `vta_start` + `vta_health` |
| 极重口音/表内两行同音 | 引擎按"宁缺勿错"放弃；主应用 UI 提示重说/手填 |

## 九、备选形态（未选，留档）

- **独立 stub APK + AIDL**：`IVtaService.aidl` 契约与 `VtaServiceImpl`（Bn 端）已实现并保留，
  但需要 Android Service 壳（`VtaNativeService`/`VtaForegroundKeeper`）与 AIDL 桩分发——对
  .NET8-only 主应用不友好，故未选。契约细节见 git 历史。
- **回环 REST（127.0.0.1）**：HTTP 化内核（token/networkSecurityConfig），隔离性最好但多一层
  服务与配置；亦未选。

## 十、与现网 C# 网关的对应关系（参考）

现网 .NET 网关的 WS 协议与内核语义的字段级映射见 `安卓化方案/README.md` §3.5。本 C ABI 面向
