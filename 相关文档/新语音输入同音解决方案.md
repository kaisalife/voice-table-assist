# 语音输入同音解决方案（现状）

> **目标**：插件即插即用——只导入表格，不维护任何语音纠错配置，换表自动生效。**边界**：语音输入段（模型/解码参数/热词格式）按现网调优冻结，本方案只做纠错与传递。

## 一、架构（三层机制，职责不重叠）

```
导表（行标签+列数）→ 识别器一次装载常驻；开会话 CreateStream(本表热词串)（切表/导入不重建）
说话 → ASR(本表热词偏置) → 数字同音归一(通用) → 表内读音吸附(partial/final 都纠) → RaNER → 检索 → cells
```

| 机制 | 作用 | 来源 | 人工维护 |
|---|---|---|---|
| 热词（按流传入） | 解码前偏置 | 行标签+位置词+数字（现网同格式） | 无 |
| 表内读音吸附 | 解码后纠错 | 本表行标签+列数枚举位置词 | 无 |
| 数字同音归一 | 值内数字同音 | 通用混淆集（硬编码一次） | 无 |

## 二、热词（按流传入，识别器常驻不重建）

| 项 | 取值 |
|---|---|
| 行标签/位置词 | 逐字空格分隔（`硬 度`、`一号/第一个/第X列/测量值X/序号X/X号列`）；含非汉字短语跳过 |
| 单字数字 | **`零…九` + `点`，刻意不含 `十`**——`十` 与 `点` 在同段声学抢分，加权 `十` 会把 `一点二` 压成 `十二`（18 条 A/B：含十 14/18 → 去十 18/18；`五十/十五点二/二十/一百` 无回归） |
| 分隔/建模单元 | 短语 `/` 分隔；`modeling_unit=cjkchar`（cjkchar 会把词再按字拆，`一 号`≡`一号`，实测逐条相同） |

**OOV 限制**：词表（BBPE 2000）缺 **振/胀/轴**；`EncodeBase` **丢字不丢行**（跳过该字、本行其余 token 保留），且 `CreateStream` 失败仅打日志、残句仍进 ContextGraph——`振 动`→`动` 等成为**假热词**。三条修法均不成立：① bbpe+配套 vocab：本模型是文本 BPE+byte_fallback 而非 byte-level BBPE，`<0xE6>` 文本经 sentencepiece DP 被拆成 ASCII 字节 token，与 vocab 的 `<0xE6>` 对不上；② cjkchar+bpe：仅字母走 BPE，汉字透传；③ bpe 整词：字节回退生效（`震动→振动`）但净效果为负（8/14 vs 9/14）——单字/数字条目被编成 `▁点` 等带前缀 token、句中永不匹配 → 小数修复丢失。→ 缺字行由吸附兜（4/4 落格）。

## 三、表内读音吸附（核心纠错）

- 词表全自动：主体=本表行标签；位置词=按列数枚举。
- 音近规则（与表无关）：忽略声调、前后鼻音、平翘舌、n/l、f/h、音节编辑距离 ≤1。
- 守卫：音节数一致；最高分 ≥0.75 且与次优差 ≥0.15；**与词表精确相等的片段不替换**（保护区）；纯数字值段跳过。失败模式安全：不像就**不填**，永不填错格。
- 插入位置：**NER 之前**（RaNER 用正确行名训练），且 **partial 也纠**（界面所见=所填）。

## 四、通用数字同音归一（DomainCorrect）

映射：十=实/石/时 · 零=灵 · 负=付 · 四=寺 · 八=巴 · 九=久 · 五=午/武 · 千=迁。
双重条件：声调相同的真同音 + 仅在数字上下文（相邻为数字）→ `实在/时间` 不会被误改。

## 五、使用约束

- **行名首句不可省略**（`测量值一` 只表示列位置）；说过行名后同会话可省略（累计上下文沿用）。
- 完全同音两行：只存在一行 → 吸附纠正 ✅；两行都在 → 说哪个填哪个 ✅；说 A 听成 B 且两行都在 → 无解。

## 六、边界与调研结论

| 情况 | 策略 |
|---|---|
| 口音重/连读/英文单位 | 放弃不填（宁缺勿错） |
| 表内两行音近 | 守卫放弃 |
| 行名含英文/符号（`PH值`） | 退回字形/语义比对（未做） |
| 小数点丢失 `一点二→十二` | **已修**：热词数字去十。机制=同段声学近并列候选抢分、热词 bonus 位置无关（token 级证实是替换非丢字；空热词/删缺字行/乱词热词均不改变结果） |

**词表扩大**：只改 `tokens.txt` 无效（decoder/joiner 输出维度固定 2002，新 id 永远不会被预测）；加**词条**随时可加且有效；扩**字表**必须改 ONNX 输出层重训。官方 multi_zh-hans 配方已发布结果**全部为 BPE 2000 + byte fallback**（xl/large/流式/离线/CTC），社区无人做过更大词表。

**换模型调研**（同一批 14 条工业用例、同套热词/吸附、MuMu x86_64）：现模型 **14/14、RTF 0.38~0.51** 仍最优。字符级候选全部根治缺字但都引入新错误：conformer-zh-2023-05-23 12/14（RTF 0.28~0.46 更快，`三点七→三十`）、wenetspeech-large 12/14（尾部重复）、bilingual-zh-en-2023-02-20 与 wenetspeech-20230615 满屏重复字（2023 年中前导出的 zipformer1 与新版 sherpa 不兼容，无热词也重复）、zh-14M 9/14、multi-zh-hans-2023-12 同为 BBPE 2002。conformer 若官方修复准确率可再评估（`hotwordDigitTen` 开关已备）。

**改进路线归档**：① 升级 sherpa + 正确 `bpe.vocab` 重试 bbpe 热词——已闭环判定**结构性不可行**（bbpe 产出 ASCII 字节 token 与 vocab 对不上；bpe 词首强加 `▁` 使数字/点条目永不匹配；cjkchar 唯一无 ▁ 但表达不了缺字——三者互斥）；② 端云混合：Qwen3-ASR-0.6B（`qwen3-asr-0.6B-int8-2026-03-25`）/ Fun-ASR-Nano（`funasr-nano-int8-2025-12-30`，int8 ≈1GB）的 RAG/上下文热词与词表彻底解耦，放服务器/PC、平板保留本地兜底；③ KWS 并行通道（行名由 3.3M 字符级 KWS 权威识别）；④ 扩词表重训（需训练资源）。

## 七、性能与可观测

- 指标看**每轮解码耗时**（partial 间隔天然 200~400ms，勿误判卡顿）。实测平均 24~35ms/轮、最大 89~156ms、RTF 0.35~0.51 → 输入段健康。
- 日志 `adb logcat -s VTA`：`[PERF]`（每轮/RTF/SUBMIT 分项）；纠错改变文本时打印 `[ASR] raw(...)`（区分"模型听错/我们改错"）。
- `pollCells` 阻塞语义（无货最多等 250ms），必须在**非 UI 线程**调用。

## 九、验收

- **PC 单测**：`jni/tests/host_test.cc` **91/91**。
- **设备端到端**（`--selftest`）：`硬度一号是十七点八四二号测量值六十`→17.84 ✅；`水围一号五米`→(1,1)=5 ✅；`气压一号零点八`→(2,1)=0.8 ✅；缺字行 `胀差二号一点二`→(4,2)=1.2 ✅。
- **多表**（`--switch-test`）：多表共存、切表不重建识别器、会话中途重建不影响在跑会话。
- **与现网对照**：同段 PCM 在 .NET 网关与安卓插件的 `cells` 应字级一致。
