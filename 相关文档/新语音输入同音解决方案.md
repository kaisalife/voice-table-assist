# 语音输入同音解决方案（现状）

> **目标**：插件即插即用——前端/实施人员**只导入表格**，不维护任何语音纠错配置；
> 表相关的同音错字自动纠正；换一张表自动生效。
>
> **边界**：语音输入段（ASR 模型、解码参数、热词格式）按现网调优结果**冻结不动**，
> 本方案只做"纠错"与"传递方式"，不改识别模型与解码配置。

---

## 一、现状架构

```
导表（行标签 + 列数）                       ← 前端唯一要做的事
   │
   ├─ 识别器：一次装载，永久常驻（无表相关状态）
   │      开会话时 CreateStream(本表热词串)   ← 热词按流传入，切表/导入都不重建
   │
   └─ 每张表：索引快照 + 吸附词表（都在开会话时按表构建）
   
说话 → ASR（带本表热词偏置）
     → 通用数字同音归一（与表无关）
     → 表内读音吸附（partial 与 final 都纠 → 界面看到的 = 会填入的）
     → RaNER → 向量检索 → cells
```

三层机制、职责互不重叠：

| 机制 | 作用 | 词表/规则来源 | 人工维护 |
|---|---|---|---|
| **热词（按流传入）** | 解码**前**偏置，让 ASR 少听错 | 本表行标签 + 位置词 + 单字数字（逐字空格分隔，**与现网 C# `BuildHotWords` 逐字一致**） | 无（导表自动生成） |
| **表内读音吸附** | 解码**后**纠错，听错也能纠回来 | 本表行标签 + 由列数枚举的位置词 | 无（导表自动生成） |
| **通用数字同音归一** | 值里的数字同音（实→十、付→负…） | 与表无关的通用混淆集（硬编码一次） | 无 |

## 二、热词：按流传入（识别器常驻不重建）

**传递方式**：sherpa 支持 `CreateStream(hotwords)`（多短语用 `/` 分隔），每路流自带热词图。
因此识别器**装载一次即可服务所有表**，切表、导入新表都**不重建识别器**。

**内容格式**：与现网 C# `TableVoiceResourceGenerator.BuildHotWords` 同格式，**仅数字集有意的差异**（见下）：

| 项 | 取值 |
|---|---|
| 行标签 | **逐字空格分隔**（`硬 度`）；含非汉字的短语跳过 |
| 位置词 | `ColumnDescriptors(columnCount)` 全部（`一号/第一个/第几列/测量值几/序号几/几号列`） |
| 单字数字 | **默认写入 `零…九` + `点`，刻意不含 `十`**。理由见 §"数值识别边界"：`十` 与 `点` 在同一段声学上抢分，给 `十` 加权会把 `一点二` 压成 `十二`。18 条小数用例 A/B：含十 14/18 → **去十 18/18**，且 `五十 / 十五点二 / 五十点零 / 二十 / 一百` 无回归 |
| 多短语分隔 | `"/"`（sherpa `CreateStream` 约定） |
| `modeling_unit` | 不显式设置（= 默认 `cjkchar`） |
| ORT 线程数 / 优化级别 | 不显式设置（= .NET `SessionOptions` 默认） |

> 逐字 vs 整词：sherpa 的 cjkchar 路径会把每个词再按 UTF-8 字拆开（`utils.cc:146-149`），
> 因此 `一 号` 与 `一号` 产生**完全相同**的 token 序列 —— 实测两者结果逐条相同，格式不是变量。

**热词覆盖的已知限制**：本模型 `tokens.txt` 是 BBPE 2000 表，常用字有 token，
**生僻字没有**（实测缺：**振、胀、轴**）。`cjkchar` 模式下逐字查表时，
`EncodeBase`（`utils.cc:40-101`）对 OOV 字是**丢字不丢行** —— 跳过该字、本行其余 token 照常保留，
且调用方 `CreateStream`（`online-recognizer-transducer-impl.h:205-237`）**失败仅打日志、仍把残句装进 ContextGraph**。
所以 `振 动`→`动`、`胀 差`→`差`、`轴 向 位 移`→`向 位 移` 会作为**假热词**生效
（实测：同一句"轴向位移二号一点二"，无热词 `周向位于`、带现状热词 `周向位移`）。

> 试过的两条修法都**不成立**，故这三行仍靠表内读音吸附兜（实测 4/4 落格）：
> ① `modeling_unit=bbpe` + 配套 `bpe.vocab`（已从 icefall 同族仓库 `zrjin/icefall-asr-multi-zh-hans-zipformer-2023-9-2`
>   下载核对，2000 个 token 与本模型逐条一致）：加载不报 OOV，但**热词完全无效**（pip 1.13.6 与设备 vendored 版一致）；
> ② `cjkchar+bpe`：热词有效，但代码里只有**字母**才走 BPE（`utils.cc:182-192`），汉字原样透传，仍不覆盖缺字。

**示例（锅炉巡检，4 列）**：热词串 395 字符；实测 `水围一号五米` 被 ASR 直接输出为
`水位一号五米`、`气压一号零点八` 输出为 `汽压一号零点八`。

> 注：本模型（`multi-zh-hans zipformer`，BBPE 2000 词表）发布包不含 `bpe.model`，
> 因此**不能**把 `modeling_unit` 设为 `bbpe`（sherpa 的热词编码会空指针崩溃）。
> 采用逐字 + 默认 `cjkchar` 即与现网一致，无需 `bpe.model`。

## 三、表内读音吸附（核心纠错）

### 3.1 词表（两个自动词表，零维护）

| 词表 | 内容 | 来源 |
|---|---|---|
| 主体词表 | `水位、汽压、汽温、风压、流量、给水温度` | 本表行标签 |
| 位置词表 | `X号 / 第X个 / 第X列 / 测量值X / 序号X / X号列` | 由列数枚举（与表无关） |

整条链路里**只有"主体"是表相关的**：值用中文数字语法（通用）、位置由列数枚举（通用）、
主体就是行标签（表自带）→ 所以纠错的目标域 = 本表词集合，无需任何人写规则。

### 3.2 通用音近模型（与表无关，硬编码一次）

| 规则 | 例子 |
|---|---|
| 忽略声调 | 井 jǐng ↔ 径 jìng；温 wēn ↔ 文 wén |
| 前/后鼻音不分 | 印 yìn ↔ 硬 yìng |
| 平/翘舌不分 | 实 shí ↔ 寺 sì；zhi/zi、chi/ci |
| n/l、f/h 不分 | 南 nán ↔ 蓝 lán |
| 音节编辑距离 ≤ 1 | 殷 yin ↔ 一 yi |

### 3.3 对齐与守卫

- 对每个候选片段逐音节比对（音节数须一致），取最高分与该片段次高分；
- **采纳条件**：最高分 ≥ 阈值（0.75）且 **与次优差距 ≥ 0.15**；
- **保护区**：与词表**精确相等**的片段一律不参与替换（否则 `一号` 会被读音相近的 `四号` 覆盖）；
- **值段跳过**：全部由数字字符构成的片段不参与替换；
- **音节数一致**：避免 2 字标签被吸到 4 字标签上。

> 失败模式安全：不像/分不清就**不替换**——漏纠只是"这一句不填"，**永远不会填错格子**。

### 3.4 插入位置：NER 之前，且 partial 也纠

```
ASR 原文 → 数字归一 → 【读音吸附】→ 用于 NER 与检索
                          ↑
                    partial（界面"实时识别"）与 final 都走这一步
```

- **必须在 NER 之前**：RaNER 是用正确行名训练的，喂"水卫"很可能抽不出主体 → 整句作废；
- **partial 也纠**：否则用户看到"气压"、格子里却填"汽压"，会以为纠错没生效。

## 四、通用数字同音归一（与表无关）

值部分不是表内词，吸附管不到，因此单独一层通用归一（`DomainCorrect`）：

| 类别 | 映射 |
|---|---|
| 十 | 实 / 石 / 时 → 十 |
| 零 | 灵 → 零 |
| 负 | 付 → 负 |
| 四 | 寺 → 四 |
| 八 | 巴 → 八 |
| 九 | 久 → 九 |
| 五 | 午 / 武 → 五 |
| 千 | 迁 → 千 |

**双重条件**：只收**声调也相同**的真同音字，且**仅在数字上下文**（前或后一个字符属于数字字符集）才替换
—— 所以"实在/时间/好天气"不会被误改。

## 五、使用约束（实施与前端须知）

### 5.1 「行名首句不可省略」

「测量值一/第一个」只表示**列位置**，不表示哪一行。首句没有行名时：

```
[ASR] final: 测量值一是五十测量值二四十九点九九第一个三十   ← 识别完全正确
[SUBMIT] 未匹配到表格项：没听出「主体 + 位置 + 数值」结构     ← 缺"行标签"→ 0 cells
```

**先说过行名**后，同一会话内可省略（累计上下文沿用）：

```
水位一号是五十测量值二是四十九点九九
→ cell: row=1 col=1 value=50 / cell: row=1 col=2 value=49.99   ← 第二句省了行名也归到"水位"
```

### 5.2 完全同音的两行（如同时有「汽压」和「气压」）

- 表里**只有**「汽压」→ 说"气压"会被吸附成"汽压" ✅
- 表里**两行都有** → 说哪个填哪个（精确匹配）✅
- 唯一无解：说了汽压、ASR 听成气压、且两行都在表里 —— 完全同音、无声学线索，**任何方法都无解**

## 六、边界与失败策略

| 情况 | 表现 | 策略 |
|---|---|---|
| 口音很重 / 连读 / 带英文单位 | 读音差太远 | 放弃不填（可加反馈提示） |
| 表内两行本身音近 | 候选分不清 | 守卫放弃（宁缺勿错填） |
| 行名含英文/符号（`PH值`、`Φ12`） | 拼音不适用 | 退回字形/语义（embedding）比对 |
| **小数点丢失**（`一点二` → `十二`，值差 10 倍） | 实测存在，机制为**近并列候选抢分**（见下"数值识别边界"） | **已修复**：热词数字集去 `十`（18/18，设备 9/9）；处理层不做猜测性改写 |

### 生僻字缺 token ⇒ 热词**丢字不丢行**（实测数据）

| 项 | 结果 |
|---|---|
| `tokens.txt` 中**有** token 的字 | 水 位 汽 压 温 风 流 量 给 度 油 差 真 空 测 值 号 序 列 移 动 向 |
| **缺** token 的字 | **振、胀、轴** → `振 动`→`动`、`胀 差`→`差`、`轴 向 位 移`→`向 位 移`（跳过该字，**残句仍进 ContextGraph 当假热词**） |

**影响与兜底**（实测，汽机巡检表）：

| 语音 | 无热词偏置时 ASR 输出 | 吸附修复 | 落格 |
|---|---|---|---|
| 油温一号五十（有热词，对照） | `油温一号五十` | — | row2 col1 = 50 ✅ |
| 振动一号零点五 | `震动一号零点五` | 震动→振动（1.00） | row1 col1 = 0.5 ✅ |
| 胀差二号一点二 | `账差二号一点二`（数字集去十后） | 账差→胀差（1.00） | row4 col2 = **1.2** ✅ |
| 轴向位移二号一点二 | `周向位移二号一点二` | 周向位移→轴向位移（1.00） | row6 col2 = 1.2 ✅ |

→ **缺字行的同音错字由吸附兜住**（三条字节回退路线均已实测无效，见 §二）；
但吸附有边界：错 2 个字或字数增减会被阈值/长度守卫拦下（宁可不填）。

### 数值识别边界：`一点二` → `十二` 的真实机制与**修复**（热词数字集去`十`）

**结论（先给答案）**：
1. **不是"少字"**：token 级看模型吐的是 `十`（替换），`tokens = [账, 差, 二, 号, 十, 二]`——
   原始输出里从来没有"点"被删掉。
2. **不是缺字行连累**：空热词（完全不给热词）同样输出 `账差二号十二`；
   把 `振动/胀差/轴向位移` 三行整行删掉也不恢复；把残句 `差`/`动` 单独当热词也不改变结果。
3. **不是随机扰动**：乱词热词（`计算机`、`阿巴`）不会翻转。
4. **真实机制**：这一句在声学上把"一+点"与"十"解码成两个**分数极接近**的候选，
   sherpa 的热词是**加性 bonus**（且**位置无关**）——给 `十` 加权会把"一+点"压掉，给 `点` 加权则救回。
   这解释了"字形差很远却互相影响"：不是字形冲突，是**同一段声学上的候选在抢分**。
5. **修复**：热词数字集去掉 `十`（保留 `零…九` + `点`）。18 条小数用例 A/B（官方 sherpa-onnx，同一模型同一音频）：

| 配置 | 命中 | 说明 |
|---|---|---|
| A 现网（`零…十` + `点`） | **14/18** | `一点二/一点五/二点五/一点二` 四处被吞成 `十二/十五/二十五` |
| B 无数字 | 14/18 | 同样四处 |
| **D `零…九` + `点`（去十）** | **18/18** | 4 处全修复；`五十/十五点二/五十点零/二十/一百` **无回归** |

设备端复验（vendored sherpa，`--selftest`，9 条）：`胀差二号一点二`→ cell 1.2、`二点五`→2.5、
`五十`→50、`十五点二`→15.2、`五十点零`→50、`二十`→20、`一百`→100，**9/9 正确**。

**机制排查证据**（同一句失败音频，只改热词内容）：

| 热词 | 结果 |
|---|---|
| 空 / 只 `十` / 只 `差`(残句) / 只 `动`(残句) / 乱词 | ❌ `账差二号十二` |
| 27 条干净短语（删掉含缺字的三行） | ❌ `账差二号十二` |
| 只 `点` / `点`+`零…九` / `点`(score=4) | ✅ `账差二号一点二` |
| 前补 0.5s 静音（无热词） | ✅ `账差二号一点二` |

> 逐字 vs 整词：`EncodeHotwords` 的 cjkchar 分支会把每个词再 `SplitUtf8`（`utils.cc:146-149`），
> `一 号` 与 `一号` 产生**相同** token 序列，实测结果逐条相同 → **格式不是变量，内容才是**。

**为什么不去处理层"救"**：把 `十二` 改回 `一点二` 要**猜**（用户也可能真说 12），猜错即 10 倍误填，
违反"宁可不填，不填错"。热词侧修复不引入任何猜测，故作为正式修法。
（另可选的零风险缓解：按该列历史值域/量级校验后提示复核。）

## 七、性能与可观测指标

**看"每轮解码耗时"，不要看"partial 间隔"**（说话本来每 200~400ms 才出一个字，
文本变化的间隔天然是这个量级，会误判成卡顿）。

日志（`adb logcat -s VTA`）：

```
[PERF] 语音输入段: 56 轮解码，平均 29ms/轮，最大 156ms/轮（分块 100ms）
[PERF] 解码 2.17s / 音频 5.60s → RTF=0.39
[PERF] SUBMIT: 文本 51 字, NER 193ms, 检索 35ms (2 项)
```

实测（MuMu x86_64，三种用例）：平均 24~35ms/轮、最大 89~156ms/轮、RTF 0.35~0.39 → 输入段健康。
单轮 >200ms 时会额外打印一行拆分明细（解码 vs 端点复位）。

**纠错可观测**：纠错改变了文本时会额外打印 `[ASR] raw(final): …`（模型原文），
便于区分"模型听错"与"我们改错"——排查"点丢失"这类问题时不必再靠外部工具离线复现。
未改变时不打印（不增加日志噪声）。

**客户端注意**：`pollCells` 是"有货立即返回、无货最多等 250ms"的阻塞语义，
必须在**非 UI 线程**调用（测试页已改为后台线程轮询，避免界面卡顿）。
