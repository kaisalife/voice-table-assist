# 安卓端语音输入表格填写——测试流程

> **被测对象**：VTA 测试版 APK（`VtaTest-x86_64.apk` 模拟器 / `VtaTest-arm64-v8a.apk` 真机）。
> 与现网 .NET 网关版功能一致，全部跑在安卓平板本地，无网络依赖。

---

## 一、实现思路

整条链路与现网一致，分三步各由一个模型接力，全部封装在插件内：

| 步骤 | 模型 | 作用 |
|---|---|---|
| ① 听写 | ASR（sherpa-onnx，含降噪开关） | 麦克风语音实时转中文文字 |
| ② 拆分 | RaNER | 句子拆成「主体 / 客体 / 值」 |
| ③ 定位 | gte 向量检索 | 「主体+客体」在当前表的向量库里找最近坐标 |

插件下发 `{ row, column, value }`，测试页表格自动回填对应单元格。

**与现网的两点差异**（测试时注意，不算缺陷）：
1. 自动纠错更强：同音错字（印度→硬度、水卫→水位）与数字抢分（一点二≠十二）在插件内自动处理，`partial` 显示的就是纠正后的文字；
2. 单会话：一个麦克风同一时刻只有一路识别，重复点「开始」会自动关旧开新（幂等，不是故障）。

## 二、部署与初始化

### 1. 安装

| 项 | 说明 |
|---|---|
| 安装包 | `VtaTest-x86_64.apk`（模拟器）/ `VtaTest-arm64-v8a.apk`（真机） |
| 安装 | `adb install -r <apk>` 或直接点击安装 |
| ⚠️ 版本 | 接口化与清理改造**之后**必须重新打包再测（构建命令见 `安卓化方案/README.md`），旧包不含最新修复 |

### 2. 初始化与导入表

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 打开 APK，点「1 初始化」 | 首次 1~2 分钟（解包模型），完成后显示两张内置表与表格网格 |
| 2 | 点「2 离线自检」 | 不需要麦克风；日志输出 final 与 cells，其中一格 17.84（链路通） |
| 3 | 点「导入表」：表名 `力学性能`，行标签逐行输入 外径/内径/表面光洁度/硬度/直线度/圆度，列数 `6` | 提示成功并自动切换到该表。**行标签顺序必须与实际表格一致**；实际表格的表头行数/行标签列位置由主应用侧登记为偏移（见用例 10） |
| 4 | 点「3 开始录入」 | 首次弹麦克风权限 → 允许；"实时识别"开始出字 |

## 三、测试用例设计

生产模板表（6×6：外径 / 内径 / 表面光洁度 / 硬度 / 直线度 / 圆度），每种用法一条用例，预期坐标沿用《测试报告》已给结果（行号从 1 起算，硬度=第 4 行）：

| # | 指南用法 | 用例输入（照指南原句，对麦克风说） | 预期 row,column,values | 目的 |
|---|---|---|---|---|
| 1 | 逐行填·X号/第几个 | 硬度，一号是五十点零，二号是四十九点九九，三号是五十一点五，四号是六十点七五，五号是六十六点七五，六号是四十八点七七 | row=4：col1=50, col2=49.99, col3=51.5, col4=60.75, col5=66.75, col6=48.77 | 基础链路 + 一行填满 |
| 2 | 逐行填·测量值 | 硬度，测量值一是五十点零，…，测量值六，四十八点七七 | 同 #1（row=4） | 助词变化 + 省略「是」 |
| 3 | 逐列填 | 第一列，硬度填十，圆度是五十 | (4,1)=10, (6,1)=50 | 先列后行的顺序 |
| 4 | 助词灵活 | 硬度，测量值二填49.99，三改为51.5，四为60.75，五八十 | 同 #1（row=4） | 填 / 改为 / 为 / 无助词 |
| 5 | 跳位填入 | 硬度，一号是五十，三号是二十 | (4,1)=50, (4,3)=20 | 不必连续、可跳 |
| 6 | 单值修改 | 硬度，二号是十 | (4,2)=10 | 只改一个格 |

**安卓端补充用例**（验证安卓版特有修复，各一条）：

| # | 用例输入 | 预期 | 目的 |
|---|---|---|---|
| 7 | 换到内置表「汽机巡检」，说：胀差二号一点二 | (4,2)=1.2 | 缺字行 + 小数点（专项修复回归） |
| 8 | 同表，说：振动一号零点五 | (1,1)=0.5 | 缺字行（振动） |
| 9 | 换到内置表「锅炉巡检」，说：水卫一号五米 | (1,1)=5 | 同音纠错（卫→位） |
| 10 | **坐标偏移**：主应用按实际表登记偏移（表头 2 行、行标签列左侧 1 列序号列 → rowOffset=2、colOffset=1），在「机加」表说：硬度一号十七点八四 | 值落在实际表格**第 3 行、第 2 列数据格**（= 插件坐标 row 0、col 0 + 偏移；换算式见《安卓化方案接口适配文档.md》§坐标换算） | 常见错误：插件返回的坐标是相对导入行清单的，前端必须加偏移，否则值会填进表头 |

> 坐标偏移注意：插件返回的 `row/column` 永远是相对**导入行清单**的序号（导入的第 1 个行标签 = row 0），
> 与真实表格在页面里的位置无关。偏移由主应用侧登记并换算（推荐），测试只核对最终落点。

## 四、测试方法

1. **先跑「2 离线自检」**：内置音频全链路冒烟，确认版本链路通（不需要麦克风，也不计入统计）。
2. **语音端到端逐条喂**：按 §三 顺序对麦克风照读，每条说完停顿约 0.3 秒（自动提交），再读下一条。
3. **每条导出结果**：输入 → 表格实际回填 → 与预期比对 → 命中 / 失败。回填明细也可从「运行日志」的 `cell: row|col|value|raw` 行核对。
4. **换表 / 换值复测**：同现网要求——把 6 条换到另一张导入表重跑；同一批句子把数值换成「一十二点五 / 零六 / 99.99 / 超一千」等。
5. **同一设备、同一 APK 版本、同一张表固定复测**，保证可复现。

## 五、结果评判

| 项 | 规则 |
|---|---|
| 单条判据 | `row / column / values` 三者全对 = 命中；任一项错、格子没填、填错格都算失败 |
| ASR 误差 | 单列记录（说了"十七"听成"十"等），**不并入**纯文本统计——那是模型层，不是插件层 |
| 自动纠错 | `partial` 显示"印度"但回填"硬度" = 正确（插件自动纠正，属设计） |
| 错误归因 | 三类：听错（ASR）、拆错（RaNER）、定位错（gte）+ 安卓特有的小数丢失回归项 |
