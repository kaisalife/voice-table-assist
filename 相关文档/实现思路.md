# 语音填表实现思路——方案说明

> 依据当前实现整理，供算法、后端及验收人员理解链路使用。
>
> **源码地址**：<https://github.com/kaisalife/voice-table-assist>
>
> 仓库**不含 models**；首次克隆后在 `app/VoiceTableAssist/` 下执行：
> `pip install modelscope ; modelscope download --model yanxiashuiyun/VoiceTableAssist --local_dir .`

## 一、问题

把一句语音（如「序号一，二号列，十七点八四」）映射到表格单元格，输出 `{ column, row, value }`。

核心难点：

1. **拆分**：从自然语言中拆出「主体 / 客体 / 值」三元组。
2. **定位**：把主客体映射到表格坐标 `(x, y)`，支持同义表达（如「二号列」「第二个」「测量值二」）。
3. **泛化**：不能靠规则穷举，需覆盖未在训练数据中出现过的说法。

---

## 二、解法

| 环节 | 模型/组件 | 作用 | 输入 → 输出 |
|---|---|---|---|
| 语音识别 | `sherpa-onnx`（本地 ASR） | 把 16kHz 语音实时转成中文文本 | 语音 → 文本 |
| 实体拆分 | `RaNER`（本地微调） | 拆出「主体 / 客体 / 值」 | 文本 → 三元组 |
| 表格定位 | `gte-base-zh` 向量检索 | 主客体拼接后查向量库，返回最近坐标 | 三元组 → `(x, y)` |

**关键设计**：

1. **主体 + 客体 = 查询短语**：如「序号一二号列」作为查询向量，命中 `(1, 2)`。
2. **向量库预生成**：导入表时，按 `行标签 × 列号` 穷举多种说法（含词序互换），写入向量库。
3. **同音/近音纠正**：ASR 之后、NER 之前做拼音→字、常见错字替换（如「付」→「负」、「实」→「十」）。

---

## 三、流程

```
语音 → ASR → 中文文本
              ↓
         RaNER 拆分 → 主体 / 客体 / 值
              ↓
         主体 + 客体 → 向量库查询 → (row, column)
              ↓
         输出 { column, row, value }
```

**步骤说明**：

1. **ASR**：只负责转文字，不识别业务术语。
2. **RaNER**：负责判断哪一部分是行、哪一部分是列、哪一部分是数值。
3. **向量检索**：把「行 + 列」拼成短语，与导入表时预置的向量算余弦相似度，最近的一条即为坐标。
4. **数值转换**：中文数字（如「十七点八四」）经 `ChineseNumeral` 转为阿拉伯数字。

---

## 四、RaNER 拆分示例

模型标签体系为 7 类 BIO：

| 标签 | 含义 |
|---|---|
| `O` | 非实体 |
| `B-SUB` / `I-SUB` | 主体（行标签，如「序号一」「外径」） |
| `B-OBJ` / `I-OBJ` | 客体（列号，如「二号列」「第二个」） |
| `B-VAL` / `I-VAL` | 值（中文数值，如「十七点八四」） |

**示例 1**

| 输入 | `序号一，二号列，十七点八四` |
|---|---|
| BIO | `序/B-SUB 号/I-SUB 一/I-SUB ，/O 二/B-OBJ 号/I-OBJ 列/I-OBJ ，/O 十/B-VAL 七/I-VAL 点/I-VAL 八/I-VAL 四/I-VAL` |
| 主体 | `序号一` |
| 客体 | `二号列` |
| 数值 | `十七点八四` |

**示例 2**

| 输入 | `序号一三号十二点零一，六号十二点零八，序号六九号十九点六六` |
|---|---|
| 输出三元组 | `序号一 / 三号 / 十二点零一` |
|  | `序号一 / 六号 / 十二点零八` |
|  | `序号六 / 九号 / 十九点六六` |

**示例 3：主客体拼接查询**

| 输入 | `序号一，二号列，十七点八四` |
|---|---|
| 查询短语 | `序号一二号列` |
| 命中坐标 | `(1, 2)` |

## 五、边界说明

| 场景 | 处理 |
|---|---|
| 主客体顺序互换 | 导入时同时生成 `(a, b)` 与 `(b, a)` 向量 |
| 「a 的 b 填 c」 | `a` 为列名、`b` 为行名，也按 `(行, 列)` 归一化写入向量库 |
| 单主体多客体 | RaNER 拆出多个三元组，分别查坐标 |
| 多主体多客体 | 按 BIO 序列结构化拆解，不依赖固定槽位 |
| 用户连续录入多列（"外径一号11.5二号22.5三号33.3"） | 静默提交后取"最后一个完整三元组"反拼为下一轮前缀，原始累计清空（见 [巧妙设计.md §1](巧妙设计.md)） |
| 用户点"结束"按钮时最后一条字还在 partial | 前端不再用固定 800ms 抢先关 socket，等服务端推回 cells 再 close；服务端在停路径把最近一条 partial `FoldPartial` 进累计再 Flush（[巧妙设计.md §3](巧妙设计.md)） |
| 多连接并发（"我开个新页"） | 单连接门卫：新连接进入时 `Cancel` 旧会话的 token，旧连接 finally 清理，新连接登记并接管（[巧妙设计.md §2](巧妙设计.md)） |
| 测试项目是否进部署包 | 3 层保险：csproj `<Compile/Content/None Remove="tests\**" />` + `publish.bat` 显式只 publish 主项目 + `publish.bat` step 1.5 兜底检查 `publish\tests`（[巧妙设计.md §4](巧妙设计.md)） |

## 末、存疑点

1. RaNER 模型在当前测试集上的精确率、召回率、F1 是否有量化指标？（参考 [巧妙设计.md §4](巧妙设计.md) 端到端测试做按行全表扫描，能在 CI 输出里看到趋势，但缺量化基准集）
2. 表格行标签本身含数字（如「序号三」）时，与列号数字的边界是否会影响拆分精度？
3. 数值超过 1000 时 `ChineseNumeral` 归零，这一上限是否需要在用户侧明确提示？
