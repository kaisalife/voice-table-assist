# VoiceTableAssist 部署文档——部署与运维

> 单进程、单端口（15232）语音表格辅助服务：本地离线 ASR（sherpa-onnx）+ 进程内 RaNER/gte-base-zh + WS/HTTP 网关，支持多表按表名热切换向量库与语音特化资源。本文面向部署与运维。

## 快速开始：两条部署路径（先分清你要哪种）

本服务有两条部署路径。**现场/目标机永远只走方式 A**；方式 B 是开发者在开发机上“出包”用的。

### 方式 A：安装包部署（推荐，最简单）

目标机**无需安装 .NET、Python、任何 SDK**，就三步：

1. 拿到 `voice-table-assist-win-x64.zip`（已含 exe + 三套模型 + sherpa 运行时 + 页面 + 脚本 + 文档）；
2. 解压到任意目录；
3. **以管理员**运行 `install.bat` —— 它会自动：放行防火墙端口 → 部署完整性自检 → 拉起服务并跑自测 → 保持服务运行。

之后浏览器打开 `http://<网关IP>:15232/` 即可用；手机/平板接入见第五节。

### 方式 B：源码部署（开发者出包）

只有需要**改代码或重新打包**时才走这条路，需开发机装 .NET 8 SDK + Python：

```powershell
git clone https://github.com/kaisalife/voice-table-assist.git
cd app/VoiceTableAssist
pip install modelscope
modelscope download --model yanxiashuiyun/VoiceTableAssist --local_dir .
dotnet build -c Release
publish.bat          # 产出 voice-table-assist-win-x64.zip（即方式 A 的包）
```

| 对比    | 方式 A 安装包          | 方式 B 源码               |
| ----- | ----------------- | --------------------- |
| 目标机依赖 | 无（self-contained） | 需构建环境                 |
| 步骤    | 解压 + install.bat  | clone + 下模型 + 构建 + 打包 |
| 适用    | 现场部署、测试验收         | 开发、定制、重新出包            |

> 简单说：**给现场/测试人员，永远发安装包让他们跑** **`install.bat`** **即可**；源码路径只是产出这个包的过程。

## 三、安装与启动

1. 解压 zip 到任意目录，例如 `D:\app\voice-table-assist`。
2. **首次以管理员运行** **`install.bat`**：会自动放行防火墙端口 15232/15433（手机/平板局域网直访必需，否则浏览器一直转圈连不上），随后跑 `deploy-check.bat /SELFTEST` 自检。
3. **服务默认不启动**，有三种拉起方式：

```powershell
# 方式A（推荐，部署后看效果）：临时拉起，关掉脚本即停
.\deploy-check.bat
#   可选：/SELFTEST（就绪后跑多表导入/热切换自测）、/PORT N、/KEEPALIVE N（自动退出）

# 方式B：直接前台运行（便于调试，Ctrl+C 退出）
.\VoiceTableAssist.exe

# 方式C：注册为常驻 Windows 服务（长期运行用；sc.exe 为系统自带，无任何外部依赖）
sc.exe create VoiceTableAssist binPath= "D:\app\voice-table-assist\VoiceTableAssist.exe" start= auto DisplayName= "Voice Table Assist"
sc.exe description VoiceTableAssist "语音巡检网关（sherpa 离线识别 + RaNER 表格填充，单进程单端口）"
sc.exe failure  VoiceTableAssist reset= 86400 actions= restart/5000
sc.exe start    VoiceTableAssist

# 停止 / 卸载：
sc.exe stop   VoiceTableAssist
sc.exe delete VoiceTableAssist
```

1. **`deploy-check.bat`** **做的事**（配合方式A）：
   - 拉起 `VoiceTableAssist.exe` 并轮询 `/api/health` 直到就绪；
   - 启动前做 **14 项部署完整性自检**（sherpa exe/原生 DLL、ASR 模型四件套、RaNER/嵌入模型、前端页面、热词文件），缺失提前 FAIL 定位；
   - 打印 `activeTable`、`provider` 与测试页 `GET /` 状态码；
   - `/SELFTEST` 时再跑一遍多表热切换自测；**结束后自动清理自测导入的数据表**（表注册表/向量索引/聚合热词全部重置，恢复出厂状态，下次由前端初始化重新导入）；
   - 然后**保持服务运行**，回车 / `Ctrl+C` / 关窗口即停止服务（连带停 sherpa 子进程）。
2. **就绪自检**（冷启动日志）：
   - `[RANER] 模型目录 = ...`
   - `[RANER] 引擎加载完成，冷启动 ...ms (RaNER N类标签)`
   - `[RANER] 自检: "外径一号十七点八四" -> 三元组=...`
   - `[RANER] 活动表: ... 向量库 ... 行x...列 x...维`
   - `sherpa-onnx 服务已就绪 (端口 6006)`

> `RANER_MODEL_DIR` 环境变量可整体覆盖 `models/` 目录（指向含 `raner/`、`embedding/` 的目录；多表目录随它定位）。

## 四、部署后验收测试（详细步骤）

> 目标：服务起来后，从“后端接口 → 电脑浏览器 → 手机/平板”逐层验证语音录入可用。按顺序走，每步有明确判据。

### 1. 后端健康检查

```powershell
Invoke-RestMethod http://127.0.0.1:15232/api/health
# 期望返回 { status:"ok", provider:"sherpa", configured:true, activeTable:"default", ... }
Invoke-RestMethod http://127.0.0.1:15232/healthz        # 兼容别名
```

- 判据：`status=ok` 且 `provider=sherpa`。这一步只验证网关在，不等同于语音链路通。

### 2. 电脑浏览器验证测试前端

1. 浏览器打开 `http://127.0.0.1:15232/`（或 `http://<网关IP>:15232/`）；
2. 页面顶部「表初始化状态」两个 chip 自动变为 **「已就绪 ✓」**（首次约几秒，构建向量库）；
3. 「当前表」下拉可选「锅炉巡检 / 汽机巡检」，下面表格随之切换。

### 3. 语音录入验证（核心）

1. 选中「锅炉巡检」，点「开始语音录入」，首次允许麦克风权限；
2. 对着麦克风说 **「水位一号是五十」**，说完**停顿约 2 秒**（自动切句提交）；
3. 表格「水位」行、1 号列格子**变绿并填入 50**；状态行显示「已更新 1 个单元格」；
4. 再说 **「汽压二号是六十」**，停顿 2 秒 —— 汽压行 2 号列填入 60（验证连续多句都能自动提交）。

> 说错/无命中时状态行显示「无命中」，日志区给出原因；麦克风无声看日志区“采集链路诊断”。

### 4. 导入 H5 表格验证（验证真实业务表格）

1. 点工具栏「**导入 H5 表格**」展开面板；
2. 粘贴实际页面的 `<table>` 源码（或先开 `/h5-sample.html` 抄样例表）；
3. 点「解析预览」→ 确认「表头行 / 行标签 N 个 / 数据列数」识别正确；
4. 按实际页面设「行偏移 / 列偏移」（默认 0），点「导入并验证」；
5. 自动切到新表，说 **「行标签 + X号」**（如「壁厚一号二点八」）→ 对应格填入 2.8。

### 5. 多表热切换验证

- 在「当前表」下拉切换「锅炉巡检 ↔ 汽机巡检」，表格立即切换；对每张表各说一句，回填不串表。

### 6. 手机/平板接入验证（见第五节）

- 手机连网关同一 WiFi → `http://<网关IP>:15232/ca.crt` 下载装证书 → 打开 `https://<网关IP>:15433/` → 允许麦克风 → 重复第 3 步。

### 7. 一键自测脚本（可选，覆盖更全）

```powershell
.\selftest\selftest.bat            # HTTP 热切换 + WS 就绪延迟 + ASR 语音端到端
.\selftest\selftest.bat -Only http # 只跑 HTTP 节
```

- 退出码 `0`=全部通过（SKIP 不算失败）；详见「十、自测」。

### 验收判据速查

| 现象                                 | 结论                                                       |
| ---------------------------------- | -------------------------------------------------------- |
| health `ok`、chips「已就绪 ✓」、说一句格子变绿填数 | **验收通过**                                                 |
| 只提交第一句、后面不填                        | sherpa 端点规则问题（`Rule2/3TrailingSilence` 需为 2.0，见「七、配置参考」） |
| 点按钮报「不支持麦克风」                       | http+IP 非安全上下文 → 走 HTTPS（第五节）或 localhost                 |
| 手机一直转圈/打不开                         | 防火墙未放行 15232/15433（用 install.bat）或手机与网关不同网段              |
| 麦克风无声                              | Windows「设置→隐私→麦克风」放行桌面应用；日志区看设备枚举诊断                      |

## 五、平板前端接入（浏览器 / 安卓 Cordova）

网关自带**两张巡检表测试前端**（`wwwroot/index.html`，表：锅炉巡检 / 汽机巡检）：页面打开即自动检查导入、
选表后点「开始语音录入」→ 识别结果按 `{row,column}` 回填单元格，已填内容本地暂存可一键清空。

### 方式1：HTTPS 浏览器直连（推荐，无需任何 APK / 编程环境）

原理：浏览器的麦克风 API（`getUserMedia`）只在**安全上下文**（`localhost` / HTTPS）开放。让网关监听 HTTPS
（`https://<网关IP>:15433/`），并在平板上安装一次我们的自签根 CA，页面即为安全上下文，麦克风直接可用。

**网关侧（一次性）：**

```bat
make-cert.bat
```

自动完成：创建/复用本地根 CA（15 年有效期）→ 签发覆盖**本机全部 IPv4 + localhost** 的服务器证书（IP 写进 SAN，
浏览器已不认仅 CommonName 的证书）→ 输出两份文件：

| 文件                  | 用途                                              |
| ------------------- | ----------------------------------------------- |
| `certs\ca.crt`      | 拷给平板安装（PEM 格式）                                  |
| `certs\gateway.pfx` | 网关服务启动时自动加载（`Program.cs` 检测到即追加 https 监听 15433） |

重新打包时 `publish.bat` 会自动把 `certs/` 带进部署包（`certs/` 已入 `.gitignore`，私钥不进仓库）。

**平板/手机侧（每台一次性）：**

#### 安卓（Android 平板/手机）

1. 手机连上网关同一 WiFi，浏览器打开 `http://<网关IP>:15232/ca.crt` 下载证书；
2. **点开下载的 ca.crt 文件**，系统自动弹出“安装证书”向导：起名 → 确定（若问用途选“VPN 和应用”）；
   少数 ROM 点文件不弹向导时，才走手动入口：设置 → 安全 → 加密与凭据 → 安装证书 → CA 证书；
3. 浏览器打开 `https://<网关IP>:15433/` → 首次弹麦克风权限，允许即可。

#### 苹果（iPhone / iPad，iOS 14.3+）

> AudioWorklet 需要 iOS 14.3+；iOS 上证书安装**必须用系统自带的 Safari**（蓝色指南针图标）——
> 第三方浏览器（iOS 版 Chrome/Edge）不会触发“描述文件”安装流程，只会显示乱码或下载失败。

1. 连上网关同一 WiFi，**Safari** 打开 `http://<网关IP>:15232/ca.crt` → 弹出“此网站正尝试下载一个描述文件” → **允许**；
2. **安装描述文件**：设置 → 通用 → VPN与设备管理（旧版叫“描述文件”）→ 已下载 `VTA Local Root CA` → **安装**（输锁屏密码）；
3. **开启信任（iOS 特有，漏了必报“无法验证服务器身份”）**：设置 → 通用 → **关于本机 → 证书信任设置** →
   把 **VTA Local Root CA** 的开关打开 → 继续确认；
4. Safari 打开 `https://<网关IP>:15433/` → 无证书警告 → 首次弹麦克风权限，允许即可。

> **常见坑**：只完成第 2 步没做第 3 步——iOS 10.3+ 手动安装的根证书默认**不启用信任**，
> 页面依然报“无效证书”。iOS 版 Chrome/Edge 共用系统信任链，第 3 步完成后它们也可正常访问。

可选：「添加到主屏幕」即可像 App 一样全屏使用（无需额外开发；iOS 用 Safari 分享菜单 → 添加到主屏幕）。

**运维要点：**

- 证书与 IP 绑定：**给网关机固定 IP**（DHCP 静态分配）。
- 网关 IP 变了：只需在网关机重跑 `make-cert.bat` + 重启服务。**平板无需任何操作**（根 CA 不变，新证书仍被信任）。
- 根 CA 私钥保存在网关机用户证书存储中，勿在公网环境使用。

**应急绕过（不装证书，仅调试用）：** Chrome 打开 `chrome://flags/#unsafely-treat-insecure-origin-as-secure`，
填 `http://<网关IP>:15232` 重启浏览器。每台手工配置、随 Chrome 版本可能失效，正式使用请走上面的证书方案。

#### 1.1 HTTPS 证书机制（make-cert.bat 做了什么）

**为什么必须 HTTPS**：浏览器的麦克风 API（`getUserMedia`）只在**安全上下文**（`https://` 页面或 `http://localhost`）
开放。平板经局域网 IP 访问 `http://<网关IP>:15232/` 不属于安全上下文，点「开始语音录入」会直接提示不支持麦克风
——这是浏览器安全策略，任何前端代码/插件都绕不过。HTTPS 是唯一的正规解法。

**信任链原理**：浏览器只信任两类证书签发者——系统预装的公共 CA，或**用户手动导入的 CA**。公共 CA 无法给纯内网
IP 签证书（没有可验证的公网域名），所以自建一条信任链：

```
VTA Local Root CA（自建根，15 年）        ← ca.crt 安装进平板 = 平板从此信任它
        └── 签发 CN=VoiceTableAssist Gateway（10 年）  ← gateway.pfx 交给网关做 TLS
```

平板访问 `https://<网关IP>:15433/` 时：网关出示服务器证书 → 浏览器用已装的根 CA 验签 → 检查访问地址是否在
证书 SAN 列表内 → 全部通过则地址栏无警告，页面即安全上下文，麦克风可用（`wss://` 同理，前端按协议自动适配）。

**SAN（最关键的证书字段）**：现代浏览器只看 Subject Alternative Name 判断"证书是否覆盖当前地址"，CommonName
早已不参与匹配。`make-cert.ps1` 自动收集本机全部 IPv4（排除 127.\* 环回、169.254.\* 链路本地）+ `localhost`
写入 SAN；也可传参追加指定 IP：`make-cert.bat 192.168.1.10`。访问地址不在 SAN 内 → 浏览器报证书不匹配 →
不受信 → 麦克风锁死。

**CA 复用（平板"只装一次"的关键）**：脚本每次先在网关机用户证书存储（`Cert:\CurrentUser\My`）里查找
`CN=VTA Local Root CA` 且未过期的证书，**找到即复用，找不到才新建**。因此网关 IP 变化后重跑脚本只是重签
服务器证书，根 CA 不变 → 平板已装的 ca.crt 依然有效，平板零操作。只有 CA 被删除重建（如清理了证书存储）时
才需要平板重装 ca.crt。

**两份文件的去向**：

| 文件                  | 内容                             | 去向                                        |
| ------------------- | ------------------------------ | ----------------------------------------- |
| `certs\ca.crt`      | 仅根 CA 公钥（PEM）                  | 拷给平板安装；泄露无风险（它只是"信任谁"的声明，不含私钥）            |
| `certs\gateway.pfx` | 网关证书 + 私钥（密码 `vta-local-2026`） | 只留在网关机/部署包；`Program.cs` 启动检测到即加载并监听 15433 |

**安全边界**：

- 自签方案仅适用于局域网，私钥密码为固定值（防误用，不构成公网级防线）；
- 证书防的是链路被窃听/篡改，不防"CA 私钥落入他人之手"——`gateway.pfx` 与网关机证书存储里的根 CA 私钥不要外传；
- 根 CA 有效期 15 年、服务器证书 10 年，期限内免维护；若证书存储被清理导致 CA 丢失，重跑脚本并在平板重装一次 ca.crt；
- 建议给网关机固定 IP（DHCP 静态分配），避免频繁重签。

## 七、多表数据管理

| 路径                                                        | 说明                                                    |
| --------------------------------------------------------- | ----------------------------------------------------- |
| `models/embedding/tables/registry.json`                   | 表名↔key + 行列/维度/导入时间 注册表                               |
| `models/embedding/tables/<key>/cell_index.bin`            | 每表向量库（**二进制 VTX1**；旧 `.json` 已弃用，用 `import_table` 重建） |
| `sherpa-onnx/hr/tables/<key>/hotwords.txt`、`hr_rules.txt` | 每表语音热词/同音纠正                                           |
| `sherpa-onnx/hr/tables/current/`                          | `default` 表资源（旧路径，兼容）                                 |

**运维要点**：

1. 首次启动无 `registry.json` 且存在旧 `models/embedding/cell_index.json` → 自动登记为 `default`。
2. **卸载/重建不删盘上文件**；同表重复导入为 last-write-wins 覆盖。
3. 注册表损坏 → 自动备份 `registry.json.bak` 并重建空清单（服务不崩）。
4. key = `SanitizeTableKey(表名)`，目录查找一律走 registry 的 `key`，避免路径穿越。
5. 容量为线性：单表索引 ≈ `rows×cols×21` 条向量 × 768 维（每格 3 种行描述 × 7 种列描述 = 21 条短语，已剔除阿拉伯数字变体与「测量值X」反序——模型词表无数字、反序非自然说法）。
6. **热词聚合与自动重启**：每表导入/刷新语音资源时，把**所有已导入表**的热词合并去重写入 `tables/current/hotwords.txt`（sherpa 仅启动时读这一个文件），并自动后台重启 sherpa（约 7s，2 秒窗口内的多次触发合并为一次）。因此：**切表识别偏置始终覆盖全部表；重启期间（约 7s）语音短暂不可用，会话会自动重试拉起**。

## 十一、GTCRN 工厂噪声降噪（可选，**默认开启**）

### 1. 这是什么

[sherpa-onnx 官方预训练 GTCRN ONNX](https://github.com/k2-fsa/sherpa-onnx/releases/tag/speech-enhancement-models)（`gtcrn_simple.onnx`，522 KB，48.2 K 参数，ICASSP 2024）跑在 .NET 进程内，对**浏览器 → sherpa-onnx** 这一段 16 kHz float32 PCM 做流式降噪：

- **稳态噪声**（风机/空压机/传送带谐波）压 15–25 dB
- **宽带噪声**（冲压/多设备混响）压 10–20 dB
- **算法延迟** ~33 ms（1 帧 STFT hop 16ms + 1 帧 lookahead）
- **CPU 增量** i5 单核 ~3%（sherpa 进程外的另一个独立 ONNX 会话）

**与中文支持的关系**：0 影响。降噪是"清理频谱噪声"，不学语义也不动 ASR 模型输入分布，对中文/英文/日文/任意语种一视同仁。启用前只要按 §3"10 句对照测试"做一遍即可放心。

### 2. 实现状态（2026-09-03 已完成并实测）

| 阶段 | 状态 | 说明 |
|---|---|---|
| ① 配置接入 + DI + ONNX 加载 | ✅ 已完成 | 读取 `AsrProvider.Denoise` 配置段；模型路径尊重 `RANER_MODEL_DIR`（开发）/ exe 目录（部署） |
| ② 状态缓存载体（`conv_cache` / `tra_cache` / `inter_cache`） | ✅ 已完成 | 形状严格对齐 sherpa-onnx 导出（`[2,1,16,16,33]`、`[2,3,1,1,16]`、`[2,1,33,16]`） |
| ③ STFT / ISTFT / 相位恢复 / 重叠相加 | ✅ 已完成 | √hann 窗 + 逐 hop 流式处理，逐行对齐 sherpa-onnx `online-speech-denoiser-stft-impl.h` 参考实现 |
| ④ 数值验证 | ✅ 已完成 |sherpa 官方带噪样例 `inp_16k.wav`：RMS 0.0850 → 0.0632（-25.7%），峰值 0.578 → 0.463；合成正弦+白噪声集成测试通过 |
| ⑤ PCM 上行链路接入 | ✅ 已完成 | `SherpaAsrBridge.ForwardBrowserAudioAsync`：byte→float→Denoise→byte；会话开始 `Reset()`、stop 时 `flush` 清态（防跨会话状态污染） |

**当前默认行为**：`AsrProvider.Denoise.Enabled = true`（实测通过后默认开启）。模型随包（publish.bat step 2.5 校验），模型缺失自动降级关闭（启动日志 `[DENOISE] WARN`）。

> 关闭方式：`AsrProvider.Denoise.Enabled = false` 并重启服务；关闭后音频链路零变化。

### 3. 实测建议（部署到新现场时）

1. **录 10 句你表里最常用的中文句**（含数字 + 行标签 + 测量值 + 各种连读），保持一致音量。
2. 在 `Enabled=false` 状态跑一遍，逐句记录 final 文本 + 端点判定时间。
3. 完成 §2 第 ③ 步 STFT/ISTFT 实现 + ④ 数值自检通过后，切 `Enabled=true` 再跑同 10 句。
4. 对比：
   - final 文本一致性 ≥ 9/10 → 放心上
   - 一致性低 → 检查 §2 第 ③ 步的相位恢复是否对齐（典型问题：窗函数/重叠率/相位差）
5. 部署到现场后**前 1–2 周**持续观察识别率与"停顿切句"表现，重点关注弱声/女声/送气音是否被压扁。

### 4. 启用/关闭方法

```json
// appsettings.json
{
  "AsrProvider": {
    "Denoise": {
      "Enabled": true,
      "ModelPath": "models/asr/gtcrn_simple.onnx",
      "NumThreads": 1,
      "SampleRate": 16000
    }
  }
}
```

`ModelPath` 相对路径以 exe 目录为基准（`AppContext.BaseDirectory`）；发布包已通过 `publish.bat` step 2.5 自动复制 `models\asr\gtcrn_simple.onnx`，启动日志会打印 `[DENOISE] GTCRN 已注册 model=…` 确认就位。模型缺失会自动降级为关闭（启动日志 `[DENOISE] WARN`）。

### 5. 常见问题

| 现象 | 排查 |
|---|---|
| 启动日志 `[DENOISE] WARN  Denoise.Enabled=true 但模型文件不存在` | `models\asr\gtcrn_simple.onnx` 没随包带出；重新 `publish.bat` 或手动从 [sherpa-onnx release](https://github.com/k2-fsa/sherpa-onnx/releases/tag/speech-enhancement-models) 拉到 `models\asr\` |
| 启用后识别率下降（弱声被清掉） | GTCRN 训练数据以成年男声为主，弱声被误判为噪声；临时方案是 `Denoise.NumThreads=1`（默认）+ 加 AGC，或在 `sherpa-onnx/hr/tables/current/hotwords.txt` 给弱声关键术语加权 |
| 启用后"四/十"等送气音对子识别率下降 | GTCRN 频谱掩码会压低短时高频；热词加大 `HotwordsScore`（默认 2.0 → 3.0）能补回 |
| 启用后端点切句变慢 | 降噪算法延迟 ~33ms，会让 2s 静默变成"2s 静默 + 33ms 推理"；如要更紧，把 `SherpaServer:Rule1TrailingSilence` 从 2.0 调到 1.8 |

## 十二、部署注意事项（踩坑实录）

以下为实测部署真实遇到过的问题，换机器部署前先过一遍。

### 1. 路径与进程

1. **zip 产物位置**：`publish.bat` 的 zip 输出在 `app\publish\voice-table-assist-win-x64.zip`（不在仓库根）。
2. **脚本必须放在 exe 同目录运行**：`deploy-check.bat` 用 `%~dp0` 定位 `VoiceTableAssist.exe`，把脚本单独拷走会报「未找到 xxx.exe」。
3. **关掉即停由** **`:cleanup`** **统一保证**：`deploy-check.bat` 在每条退出路径（回车 / `Ctrl+C` / 关窗口 / 自测失败退出）都会先 `taskkill /F /T` 停掉本次拉起的 `VoiceTableAssist` 与 sherpa 子进程。但**强杀 cmd 进程本身**（如任务管理器结束）不会触发清理，此时需手动补停：
   ```bat
   taskkill /F /IM VoiceTableAssist.exe /T
   taskkill /F /IM sherpa-onnx-online-websocket-server.exe /T
   ```
4. **端口被占用会明确拒绝**：启动前若 15232 已有实例（比如上次忘了停），`deploy-check.bat` 会直接报「端口已被占用」并退出，避免把旧实例的应答误判为新启动成功。

### 2. 网络与编码（Windows 特有坑）

1. **探活用 curl，地址用** **`127.0.0.1`，不要用** **`localhost`**：Windows 上 `localhost` 先解析到 IPv6 `::1`，而 Kestrel 实际只绑 IPv4（`netstat -ano | findstr 15232` 显示 `0.0.0.0:15232`）。`curl http://localhost:15232/api/health` 会因 IPv6 回退等待而超时误判「服务未就绪」。所有自检/自测脚本已统一改为 `curl http://127.0.0.1:15232/api/health`。
2. **HTTP 请求带中文 body 用** **`curl --data-binary @文件`** **方式，避免 cmd 参数编码问题**：中文 body 若走 cmd 命令行参数，会因系统代码页（非 UTF-8）被改码，`"力学性能"` 会在传输途中变成 `"????"`——服务端拿到损坏表名后生成 `key=table`、向量索引查不到任何数据。正确写法：
   ```bash
   curl -sS -X POST -H "Content-Type: application/json; charset=utf-8" --data-binary "@req.json" "http://127.0.0.1:15232/api/table/import"
   ```
   服务端无需任何改动，问题永远在客户端发送侧。诊断特征：日志出现 `[IMPORT] 表 ????(key=table)`，问号个数 = 汉字个数。
3. **部署/打包/自测脚本已全部改为纯批处理(.bat)，脚本源码仅用 ASCII 字符，无中文编码问题**。

### 3. 运行期文件

1. **registry 损坏不要慌**：`models/embedding/tables/registry.json` 写坏（如强杀进程导致半截 JSON）时，服务启动会自动备份为 `.bak` 并重建空清单，随后重新 `/import_table` 即可恢复，服务不崩。
2. **wwwroot 缺失 = 测试页 404**：构建输出目录（bin）下可能没有 wwwroot（Production 静态资源不经编译拷贝），打包产物由 `dotnet publish` 自动带上。若手动从 bin 目录布置，记得确认 `wwwroot/index.html` 存在；否则页打不开但 API 一切正常，日志会有 `The WebRootPath was not found` 警告。

### 4. ASR 相关

1. **冷启动约 15\~20 秒属正常**：RaNER/gte 引擎加载 + sherpa 加载模型 + 热词编码。sherpa-onnx 日志中 `Failed to encode some hotwords, skip them` 为跳过不可编码热词的常规告警，不影响识别；`handle_read_frame error ... End of File` 为无音频时的探活断连记录，也可忽略。
   > 懒加载模式（2026-08-28 起，默认开启）下该冷启动从「服务启动时」推迟到「首次使用时」：首次文本查询 +1.5\~2s，首次语音连接 +8\~10s（期间前端会收到 loading 进度帧）；空闲 30s（`Models:IdleUnloadSeconds`）自动卸载，下次使用重复上述加载。若不接受首次延迟，设 `Models:LazyLoad=false` 恢复启动即加载。

### 5. 语音链路（实机调试补录，均已代码/配置固化）

1. **热词文件缺失 → sherpa 启动即退**：sherpa 启动时必须能读到 `--hotwords-file` 指向的文件。干净部署包里还没有导入过任何表，该文件不存在。已双保险：`publish.bat` 预置空文件；`SherpaServerManager` 启动前也会自愈创建（日志「热词文件不存在，已自动创建空文件」）。导入表后会自动聚合填充。
2. **热词必须是字级 token 空格分隔**：中文模型词表按单字切分，热词行必须写成 `水 位`（`join(' ')`），整行连写映射不到 token 直接失效；且模型词表无 ASCII 数字，`1号` 这类短语不可能被识别，生成时已跳过。前端"语音热词已刷新"但识别仍差 → 先查 `sherpa-onnx/hr/tables/current/hotwords.txt` 内容格式。
3. **切表后热词不自动跟随是设计约束**：sherpa 仅在启动时读一次热词文件。已实现**聚合方案**：每次导入/刷新表资源时把所有已导入表的热词合并去重写入 `tables/current/hotwords.txt`，并自动后台重启 sherpa（约 7 秒，2 秒窗口内的多次触发合并为一次）。测试页每次打开也会对已存在的表轻量刷新语音资源（`/api/table/voice`，不重建向量库）。向量索引本身按会话表切换，无需重启。
4. **端点检测必须开启**：`--enable-endpoint=false` 时流式识别永远不输出 final，服务端"说完停顿自动提交"不会触发（表象：识别文本一直停在「识别中：…」）。已固化默认配置：`EnableEndpoint=true` + `Rule1TrailingSilence=2.0`（说完停顿 2 秒自动切句提交），服务端静默提交延时 `SilenceMs=300`。换 sherpa-onnx 版本时注意参数名差异（新版是 `--rule1-min-trailing-silence` 分离式参数，旧版才有 `--rules1`）。
5. **累计文本提交后保留**：后续语句常省略行标签（如说完「水位一号是五十」再说「二号是六十」），提交后清空会丢失主体。已改为提交后保留累计、每次基于完整上下文解析（重复格子以相同/更新值覆盖，无害）；仅超 `MaxChars=500` 字时整体清空重录。
6. **浏览器麦克风三坑**（测试前端）：
   - `getUserMedia` 仅在 **localhost / HTTPS** 安全上下文可用，局域网 IP 直连会被禁（安卓用 Cordova 壳或者是ca解决）；
   - 权限曾被设为「阻止」后 Chrome **不再弹窗**直接拒绝，需到地址栏左侧图标 → 网站设置 → 麦克风改「允许」，或 `chrome://settings/content/microphone` 放行；页面日志区已内置权限状态检测与设备枚举诊断；
   - **前端文件更新后浏览器可能用旧缓存**：静态文件已加 `Cache-Control: no-cache`（协商缓存），正常刷新即可；脚本引用带 `?v=2` 版本参数，前端有改动时记得递增版本号。

### 6. 运行环境

1. **目标机不需要装 .NET**：self-contained 包自带运行时；只需 Windows x64。磁盘预留 ≥ 2 GB（解压后约 2 GB，含三套 ONNX 模型）。**内存（懒加载模式）**：待机（语义引擎卸载后）约 300MB + sherpa 常驻约 680MB；使用中峰值约 2GB，语义引擎空闲 180s 自动回落。
