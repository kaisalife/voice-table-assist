# RaNER 模型训练方法——操作手册

> 依据 ModelScope 微调流程整理，供算法工程师复现与迭代使用。

## 一、概述

基于 ModelScope 的 RaNER 预训练模型 `damo/nlp_raner_named-entity-recognition_chinese-base-news`，在自建语音巡检数据集上微调，输出 ONNX 格式供 C# 后端（`Microsoft.ML.OnnxRuntime`）调用。

**链路**：生成数据 → 环境准备 → 微调训练 → ONNX 导出 → C# 部署。

---

## 二、标签体系

### 1. 7 类 BIO 标签

| 标签 | 含义 |
|---|---|
| `O` | 非实体 |
| `B-SUB` / `I-SUB` | 主体（行标签，如「外径」「序号三」） |
| `B-OBJ` / `I-OBJ` | 客体（列号，如「一号」「第一个」） |
| `B-VAL` / `I-VAL` | 值（中文数值，如「十七点八四」） |

### 2. 标注规则

| 规则 | 说明 |
|---|---|
| SUB 不直接后跟值 | 主体后必须接客体，再由客体接值 |
| OBJ 直接后跟值 | 客体后可接值，或连接词 + 值 |

## 三、生成训练数据

### 1. 脚本

`generate_data.py`

### 2. 数据来源

基于生产模板 `moban.txt`：6 行 × 6 列表格，行标签为「外径 / 内径 / 表面光洁度 / 硬度 / 直线度 / 圆度」，列号为 1~6。

### 3. 数据组成

训练数据分两部分，各占约一半，按 9:1 划分训练集/验证集。

**第一部分：硬性全排列（确定性覆盖）**

| 函数 | 作用 |
|---|---|
| `inspection_single_full()` | 所有 `(行标签 × 列号)` 组合的多样式表达（带/不带标点、连接词、前置/后缀、列前/行前） |
| `inspection_single_sub_multi_col()` | 单主体多客体全排列（`C(6,2)+C(6,3)+...+C(6,6)=56` 种列组合） |
| `multi_sub_multi_obj()` | 多主体多客体组合 |
| `inspection_col_first()` | 列前多行（列号为主体统摄多行） |
| `inspection_ordinal_row()` | 序号为主体（序号三 / 第一个 / 十一点零等），含 11 种单实体变体 + 1500 多客 + 1000 多主体 |

**第二部分：随机化组成（扩充变体）**

| 函数 | 作用 |
|---|---|
| `inspection_same_row()` | 同行多列 |
| `inspection_cross_row()` | 跨行 |
| `inspection_with_connectors()` | 带连接词（填 / 是 / 为 / 等于 / 约 / 达到 / 写 / 输入 / 改成 / 设为） |
| `inspection_long()` | 长序列（4~6 行，每行 2~4 列） |
| `generalized_random(2500)` | 完全随机化拼接，50% 概率用序号做主体 |

### 4. 数值生成

| 项 | 规则 |
|---|---|
| 小数位 | 80% 两位小数、10% 一位小数、10% 整数 |
| 范围 | 0~100 |
| 形式 | 全部中文数字（如「十七点八四」），无阿拉伯数字 |

### 5. 输出文件

| 文件 | 说明 |
|---|---|
| `train.bio` / `dev.bio` | 训练/验证数据（BIO 格式） |
| `train.json` / `dev.json` | 训练/验证数据（JSON 格式） |

## 四、环境准备

### 1. 脚本

`setup_finetune.sh`

### 2. 执行环境

ModelScope 云平台 GPU 环境。

### 3. 主要操作

1. 创建 Python 虚拟环境，`--system-site-packages` 复用平台预装的 torch/cuda 等大包。
2. 安装 `pytorch-crf`（从 GitHub 源码）、`transformers`、`tqdm` 等依赖。

## 五、微调训练

### 1. 脚本

`train.py`

### 2. 模型架构

`BertCRF`：

```
BERT (Chinese base) → Dropout → Linear → CRF
```

### 3. 权重映射

| 源权重 key | 目标 key | 操作 |
|---|---|---|
| `encoder.*` | `bert.*` | 适配标准 `BertModel` |
| 原 CRF / Linear 层 | — | 丢弃 |

重新初始化分类头和 CRF 层。

### 4. 训练参数

| 参数 | 值 | 说明 |
|---|---|---|
| `MAX_LEN` | 128 | 最大序列长度 |
| `BATCH_SIZE` | 128 | 批次大小 |
| `EPOCHS` | 10 | 最大训练轮次 |
| `LR` | 2e-5 | 学习率 |
| `WARMUP_RATIO` | 0.1 | 预热比例 |
| `OPTIMIZER` | AdamW | 优化器 |
| `SCHEDULER` | OneCycleLR | 学习率调度 |

### 5. GPU 加速

| 项 | 配置 |
|---|---|
| 混合精度 | `torch.amp.autocast` + `GradScaler` |
| cuDNN | `cudnn.benchmark = True` |
| 矩阵精度 | `float32_matmul_precision = "high"` |
| 数据加载 | 16 个 DataLoader workers，`pin_memory` + `prefetch` |

### 6. 早停策略

| 策略 | 规则 |
|---|---|
| 常规早停 | 验证集 F1 连续 5 轮不提升则停止 |
| 积极早停 | 与上次训练最优 F1 对比，若未提升且差距 ≤ 0.01，提前结束 |

### 7. 输出

| 文件 | 说明 |
|---|---|
| `output/best_model.pt` | 最优模型权重 |
| `output/config.json` | 模型配置 |
| 分词器文件 | 与预训练模型一致 |

## 六、模型导出

### 1. 脚本

`export.py`

### 2. 导出产物

| 文件 | 说明 |
|---|---|
| `model.onnx` | 只包含 BERT + Linear（输出 emissions），CRF 解码在 C# 端实现 |
| `crf_transitions.npy` | 7×7 CRF 转移矩阵，C# 端做 Viterbi 解码 |
| `config.json` | 标签列表、`max_len` 等 |
| `vocab.txt`、`tokenizer.json` 等 | 分词器文件 |

### 3. 验证

导出后自动对比 PyTorch 与 ONNX 输出误差。

---

## 七、部署到 C# 服务

### 1. 目标目录

`text_to_json/models/raner/`

### 2. 部署步骤

1. 复制 `model.onnx`、`model.onnx.data`、`vocab.txt` 到目标目录。
2. 将 `crf_transitions.npy` 转换为 `crf_transitions.json`（7×7 浮点数组）。
3. 重启 C# 服务。

### 3. C# 端推理流程

1. 逐字分词。
2. ONNX 推理得 emissions。
3. Viterbi 解码（使用 CRF 转移矩阵）→ BIO 标签。
4. 从 BIO 标签中提取 SUB-OBJ-VAL 三元组。
5. 通过 embedding 向量检索匹配行列坐标。

## 九、快速开始

```bash
# 1. 生成数据
python generate_data.py

# 2. 环境准备（ModelScope 云平台）
bash setup_finetune.sh

# 3. 训练
source .venv/bin/activate
python train.py

# 4. 测试
python test.py

# 5. 导出 ONNX（C# 与 JS 均使用 ONNX 格式部署）
python export.py
```
