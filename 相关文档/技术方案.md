# 语音表格辅助技术方案——模型选型与训练

> 依据当前实现整理，供技术评审与后续迭代参考。

## 一、语音 → 文字模型（ASR）

### 1. 主流模型及优缺点

| 模型/方案                    | 优点                       | 缺点                             | 适用场景        |
| ------------------------ | ------------------------ | ------------------------------ | ----------- |
| OpenAI Whisper           | 多语言能力强、开源、社区生态成熟         | 模型较大、实时性一般、需较高算力               | 离线转写、多语言混合  |
| Wav2Vec 2.0 / XLS-R      | Meta 开源、支持微调、学术引用广       | 中文效果需额外微调、工程链略重                | 英文/多语言、研究场景 |
| Conformer + Kaldi/sherpa | 工业级流式识别、实时性好、可本地化        | 中文模型需专门训练、生态碎片化                | 实时语音交互、端侧部署 |
| 商业云 ASR（阿里云/讯飞/腾讯云）      | 准确率高、接入简单                | 需联网、按量计费、数据外泄风险                | 快速上线、预算充足   |
| sherpa-onnx              | 本地离线、C++ 运行时、支持流式、模型选择灵活 | 模型质量依赖所选 checkpoint、热词/纠错需自行维护 | 私有化部署、工业现场  |

### 2. 选择的模型与效果

**选择模型**：`sherpa-onnx`（本地流式 ASR）。

**选型理由**：

1. **离线运行**：目标场景为工厂/现场，网络不稳定，必须本地部署。
2. **流式识别**：支持 WebSocket 实时推流，边说边识别。
3. **资源可控**：可选不同尺寸模型，在准确率与延迟间取舍。
4. **集成方便**：C# 进程内启动 sherpa-onnx server，通过本地 WebSocket 转发音频。

**目前效果**：

| 项   | 现状                                          |
| --- | ------------------------------------------- |
| 采样率 | 16kHz，float32 PCM                           |
| 冷启动 | 首次语音连接约 8\~10s（含模型加载），期间前端收到 `loading` 帧    |
| 实时性 | 流式返回 `partial` / `final` 结果                 |
| 准确率 | 标准普通话、环境噪声可控时，常规数字/术语识别可用；存在同音字误差，需后端同音纠正兜底 |

## 二、文字 → JSON 模型

### 1. 主流模型及优缺点

| 模型/方案              | 优点                     | 缺点            | 适用场景        |
| ------------------ | ---------------------- | ------------- | ----------- |
| BERT-CRF           | 准确率高、可解释性好、适合槽位固定      | 需标注数据、泛化能力中等  | 结构化抽取、表单填槽  |
| BiLSTM-CRF         | 轻量、训练快                 | 上下文理解弱于 BERT  | 简单序列标注      |
| GPT / 大模型          | 零样本/少样本能力强、说法灵活        | 模型大、延迟高、输出不稳定 | 开放域对话、复杂语义  |
| 通用信息抽取（UIE 等）      | 针对中文优化                 | 需适配领域         | 中文 NER、关系抽取 |
| RaNER (ModelScope) | 中文实体识别专用、模型适中、可导出 ONNX | 需微调、领域适配      | 中文 NER、工业语义 |

### 2. 选择的模型

| 环节   | 模型                                                                     | 作用                    |
| ---- | ---------------------------------------------------------------------- | --------------------- |
| 实体拆分 | `RaNER`（`damo/nlp_raner_named-entity-recognition_chinese-base-news`）微调 | 拆出「主体 / 客体 / 值」       |
| 表格定位 | `gte-base-zh` 向量检索                                                     | 「主体 + 客体」拼成短语，查向量库得坐标 |

**选型理由**：

1. **RaNER 适合中文实体边界**：对「主体 / 客体 / 值」的 BIO 标注友好。
2. **gte-base-zh 语义向量**：支持「词面不同、语义相同」的模糊匹配，解决同一单元格的多种说法。
3. **均可本地运行**：满足离线部署需求。

### 3. 训练方法

1. **数据生成**：`generate_data.py` 基于 `moban.txt` 模板，生成 6×6 表格的多种说法，覆盖行先说/列先说、带/不带连接词、单主体多客体、多主体多客体、长序列等。
2. **标签体系**：7 类 BIO（`O`, `B-SUB`, `I-SUB`, `B-OBJ`, `I-OBJ`, `B-VAL`, `I-VAL`）。
3. **微调**：`train.py`，BERT + CRF 架构，AdamW + OneCycleLR，参数如下：

| 参数           | 值          |
| ------------ | ---------- |
| `MAX_LEN`    | 128        |
| `BATCH_SIZE` | 128        |
| `EPOCHS`     | 10         |
| `LR`         | 2e-5       |
| `OPTIMIZER`  | AdamW      |
| `SCHEDULER`  | OneCycleLR |

1. **导出**：`export.py` 输出 ONNX + CRF 转移矩阵 + 配置文件，供 C# 端 Viterbi 解码。
2. **部署**：复制到 `text_to_json/models/raner/`，重启服务。

### 4. 目前效果

| 项      | 现状                        |
| ------ | ------------------------- |
| 训练覆盖句式 | 拆分稳定                      |
| 未生成说法  | 依赖 gte 向量语义泛化             |
| 边界     | 句子越拗口、冗余越多、词序越乱，越可能掉回相邻坐标 |
